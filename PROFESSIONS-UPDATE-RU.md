# Territory — профессии, ресурсы и ремесло

## Реализовано в исходниках этого обновления

- Пять профессий: кузнец, алхимик, ремесленник, ювелир и инженер.
- Персонаж может выбрать только одну профессию.
- Выбор сейчас бесплатный только для тестирования; покупку постоянной лицензии намеренно не подключали.
- Любой персонаж может собирать железную руду, травы, древесину и магические кристаллы — профессия для этого не нужна.
- Ресурсы и предметы создаются в игровом инвентаре, а состояние профессии и опыт хранятся внутри `GameState` и идут в существующее облачное сохранение игры.
- Добавлены рецепты по профессиям: экипировка, зелья, эликсиры и торговые ремесленные товары.
- Опыт ремесла повышает мастерство до 300-го уровня; рецепты высокого уровня становятся доступны по мере прокачки.
- Базовые характеристики изготовленной боевой экипировки намеренно повторяют бюджеты уже имеющихся предметов магазина, чтобы не нарушать текущий баланс.
- Существующие бои, персонаж, инвентарь и схема базы данных не заменяются.

## Что сознательно не включено

- Telegram Stars и любые другие платежи не подключены и не нужны для проверки игровой механики на этом этапе.
- GRAM не подключён.
- Общий аукцион между разными игроками ещё не активирован. Интерфейс не делает фиктивные продажи и не начисляет золото за локальные тестовые действия. Для реального рынка нужен серверный слой транзакций, который защитит предметы и золото от дублирования и гонок с обычным автосохранением.
- Не добавлялись и не применялись новые миграции базы данных.

## Проверки

- Модули типов, баланса экипировки и профессий прошли отдельную строгую проверку TypeScript.
- Добавлен повторяемый тест `npm run test:professions`: он проверяет 5 профессий, каталог рецептов, рост мастерства до 300-го уровня, списание ресурсов при крафте и отказ при нехватке материалов.
- `npm run test:balance` проходит.
- Полную команду `npm run build` локально подтвердить не удалось: запросы `npm ci` зависают по тайм-ауту, а доступные локальные пакеты React/Vite/TypeScript types неполные. Поэтому полная сборка приложения не объявляется проверенной. После загрузки частей GitHub Actions сможет выполнить сборку на полноценном runner-е.
