# TERRITORY — реальное серверное усиление защиты без сброса игроков

**Дата:** 15 октября 2026. Исходная рабочая ветка GitHub `main`: `dc767e76b569a63a386453fe5fb784f15f181bdb` (STAGE6). Полный ZIP заменяет файлы приложения, а не точечный патч.

## РЕАЛЬНО ВЫПОЛНЕНО в рабочей Supabase

В проекте Supabase `wmyrdpbwlkzsktnhookx` миграцией `territory_economy_live_guard_audit_20261015` установлены и включены два триггера таблицы `public.players`:

1. **Проверка сервером формы сохранения** (`territory_economy_guard_before_v1`). Когда обновляется `game_state`, сервер требует валидные целочисленные значения золота, алмазов, уровня, боевых камней; сверяет золото, алмазы и уровень со столбцами `players.gold`, `players.gems`, `players.level`; отклоняет отрицательные камни, дневной счётчик покупок более 25 и прочие некорректные значения. Неправильное обновление отменяется целиком. Предыдущие данные игрока сохраняются.
2. **Версия сохранения от серверных часов.** При изменении `game_state`, золота, алмазов или уровня PostgreSQL сам выставляет строго возрастающее `updated_at`. Клиент не определяет эту версию своим временем; это усиливает оптимистическую защиту от перезаписи данных другим окном.
3. **Неизменяемый для клиентов журнал изменений** (`territory_economy_audit_after_v1`, таблица `territory_economy_audit_v1`). Сервер записывает до/после золота, алмазов, уровня, камней, дневных покупок и главы, а также ID пользователя и время изменения. Не записывает личные сообщения, полный инвентарь, Telegram ID или полный `game_state`. Подозрительные единичные скачки (>500 алмазов, >250000 золота, >25 камней, >5 уровней) получают метку для проверки, **но игроки автоматически не блокируются**.
4. Роль `authenticated` не имеет `SELECT`/`INSERT` для таблицы аудита и права `EXECUTE` на приватный триггер.

**Подтверждение после серверной миграции:** триггеры включены, аудиторских записей до новых действий нет, сохранилось **41 игроков, нулевое количество пустых сохранений и отрицательных кошельков**. Ни одной строки `players` не обнуляли или перезаписывали. SQL-исходник: `supabase/production/territory_economy_guard_20261015.sql`. Повторно накатывать его на работающую базу **не требуется**.

## КЛИЕНТСКОЕ ПРИЛОЖЕНИЕ

- Добавлена предварительная проверка `src/game/economyInvariant.ts`. Если локальное состояние повреждено или содержит некорректную валюту, игра не пытается отправить такой снимок на сервер: показывает уже существующее предупреждение о неудачном сохранении вместо риска перезаписи аккаунта.
- Существующая миграция старых аккаунтов, профессии, PvP, аукцион, спутники, предметы, VIP и активные экраны сохранены. Подлинные данные игрока не меняются при установке ZIP.
- Добавлены `scripts/check-stage7.mjs` и тесты предыдущих этапов. Проверена синтаксическая корректность и логика защитных проверок, но **не проводилось** полноценное интеграционное тестирование боевого PvP и всех серверных RPC, не выполнена локальная `vite build` (изолированная среда не смогла завершить `npm ci`). Сборку нужно подтвердить по GitHub Actions после распаковки.

## НЕ НАЗЫВАТЬ ПОЛНОЙ ЗАЩИТОЙ ОТ НАКРУТКИ

**Это работающие серверные проверки и аудит, но не полноценная server-authoritative экономика.** Пока `authenticated` может обновлять `players.game_state`, `gold`, `gems`, `level` через Data API, злоумышленник может создать *согласованные* ложные значения. Журнал позволит обнаружить часть таких операций, но не предотвратит умышленное дробление. Лимит «25 камней в сутки» тоже ещё не защищён от обхода прямым запросом: дневной счётчик пока клиентский. Нельзя утверждать, что накрутка полностью устранена.

Для полной защиты нужны проверенные сервером игровые действия (боевые награды, магазин, кузница, задания и бесплатные награды), отзыв прямой записи **только после их переноса** и сверки кошельков. Резкий `REVOKE` прямо сейчас сломает действующие сохранения 41 аккаунта. Серверный аукцион и оплата не включены.

**Обход release gate:** репозиторий всё ещё содержит `.github/workflows/territory-pages-repair.yml`, который публикует сборку при `economy-release.json.ready=false`. ZIP-установщик исключает папку `.github`, а подключённый GitHub-коннектор отказал в изменении workflow с `403`. Обойти это безопасно ZIP-пакетом нельзя. Этот пробел пока остаётся открытым.
