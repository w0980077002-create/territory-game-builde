## Непосредственный порядок развёртывания

1. **Сначала тестовая БД.** Нужна отдельная Supabase development branch
   фактического проекта или сопоставимый тестовый PostgreSQL. Supabase показывает
   цену ветки `$0.01344/час`; её создание требует явного подтверждения стоимости
   владельцем. Ветка не содержит реальных данных игроков — миграции нужно
   дополнительно тестировать с безопасными fixtures старых профилей.
2. Снять read-only baseline существующих таблиц, функций, grants, cron,
   текущего server release; проверить восстановимую резервную копию
   production. Никаких автоматических seed/переносов из `players.game_state`.
3. **Кланы:** на тестовой ветке проверить точный generated
   `territory_stage1_clans_install.sql`, ACL/RLS и CAS; затем однократную
   установку на рабочую базу с подтверждённым защищённым кошельком лицензии.
   Не повторять seed красных алмазов.
4. **Недельные сезоны:** сделать diff текущих установленных процедур
   против `territory_weekly_seasons_v1.sql`; установить исправления захвата и
   закрытия, админские RPC/Edge Function, проверить почтовую транзакцию, только
   затем cron и отдельную активацию утверждённых наград. Не пересчитывать
   задним числом историю.
5. **Серверные слоты:** проверить приватные таблицы зала, транзакционные
   блокировки на двух PostgreSQL-подключениях, отказ от двойного списания и
   повторного начисления при timeout. И только после этого включать реальную
   игру вместо демо. Не выдавать призы на стороне клиента.
6. **Аукцион:** пока **заблокирован**: нет трёх обязательных таблиц Stage3
   и доверенного перехода кошелька/инвентаря. Не создавать пустую копию
   кошелька и не включать торговлю поверх неподтверждённых клиентских предметов.
7. Сверить мобильный Telegram/iPhone/Samsung и GitHub Pages с реальным RPC,
   безопасностью повторов и существующим входом в админку (пять нажатий).
   После полного прогона интегрировать PR и включать функции по отдельным
   серверным флагам. При проблемах выключать флаг, не сбрасывать игроков.

Запрещено: менять другую одноимённую БД вместо активной, массово пересевать
кошельки, удалять старые сохранения или выдавать игрокам доступ к
`SECURITY DEFINER` внутренним RPC без явных ACL. Новые публичные таблицы
должны получать явные `GRANT` и RLS (изменение Supabase по умолчанию с
30.10.2026).
