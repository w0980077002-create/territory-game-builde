## Сквозная интеграция, которую уже проверили

`territory_v1_completion_integration.sql` связывает проверенные исходы боя с настраиваемыми активностями/фондами в той же транзакции. Таблицы соответствия пусты: источник не придуман вместо решения по контенту. События получают отдельные стабильные ID; повтор не увеличивает прогресс.

`check-v1-integration.mjs` устанавливает все новые SQL-сценарии в одну изолированную PostgreSQL PGlite с двумя аккаунтами. Проверяет неизменность строк игроков при установке; перенос экипированного самоцвета покупателю предмета; аукцион → Stars → существующий atomic mail с одним согласованным балансом; самоцветы → VIP → бой ровно один раз; исход → активность/фонд → настоящая наградная почта; Stars → премиальный фонд без придуманной валютной награды. Тестовые цены/коэффициенты находятся только в тестах, staged-каталоги их не содержат.

## Проверки

Общий запуск: `npm run test:v1-completion` (10 целевых скриптов, включая SQL, чистый движок, клиентские контракты, комбинированный сценарий и offline TypeScript Edge entrypoints). Дополнительно: `npm run typecheck`, `npm run build`.

Регрессии: `test:economy`, `test:pve`, `test:balance`, `test:saves`, `test:stage5`, `test:professions:stage8`, `test:master-license`, `test:events`; также release invariants, economy receipts foundation, inventory ACL, auth mock и edge identity. Это локальные проверки. PGlite не подтверждает реальные многосоединительные гонки, production-данные, Telegram-платёж, скорость мобильного UI или восстановление бэкапа.

## Сохранность и выпуск

Ни один production-запрос изменения не выполнен, SQL/Edge Functions не установлены, ветка не отправлена, Pages не опубликована. Новые экономические флаги выключены. Существующие валюты/никнеймы/VIP/лицензии/инвентари не обнуляются и не импортируются из клиентского сохранения как доказанный баланс. Старые ресурсы получают метаданные срока только после явной сверки ровно того же количества, без выдачи новой суммы.

Основная совместимая правка действующего кода — парсер `stage8CraftApi.ts`, принимающий подтверждённый сервером срок материалов; визуальные компоненты, админский вход в пять нажатий и TERRITORY 2.0 не изменены.

**Нельзя просто включить флаг аукциона в существующей игре.** После reviewed cutover прямые изменения валют с клиента отклоняются, доверенные серверные выплаты синхронизируют проверенные кошельки. Пока текущие клиентские начисления PvE/заданий не перенесены на проверенные серверные маршруты, включение нарушит их сохранение. Этот этап не замаскирован под завершённую миграцию. Нужны staging, проверка источников и клиентов, резервная копия и отдельное подтверждение релиза владельцем.

Базовые зависимости staged-пакетов: действующие Stage3/Stage5, Stage8 professions, master-license shop, fortune VIP, atomic mail v2. При локальной совместной проверке порядок: Stage5 → atomic mail v2 → auction completion → progression completion → monetization completion → combat completion → completion integration. Это порядок тестирования, а не разрешение применять сценарии к production.

Из источников не найден отдельный `TERRITORY_1_0_GAP_AUDIT_2026-10-28.md`. Отсутствующие цены, коэффициенты и контент не восстановлены догадками. Внешний веб-магазин только описан; криптоплатежи не запущены, GRAM и Toncoin не отождествлены.
