# Дополнение к PR #36: награды и исходная ошибка CI

## Настоящие награды

Все суммы определяет сервер; клиент не присылает ни количество, ни свойства предмета. Каждая клетка сохраняет прежнее золото зала и дополнительно получает приз по индексу. Старт, клетки 6/14/21 и остаток 0 дают только золото/событие.

| Индекс клетки modulo 6 | Дополнительный приз ×1 | Приз ×10 |
| --- | --- | --- |
| 1 | 2 синих алмаза | 20 |
| 2 | 5 боевых камней | 50 |
| 3 | 3 материала кузницы | 30 |
| 4 | 1 зелье здоровья | 10 |
| 5 | 1 эликсир силы | 10 |

Сокровище добавляет 3 синих алмаза (×10 — 30) и прежние 25 золота с множителем. Подарок дня: 2 общих билета зала и 1 зелье здоровья. Награды за круг N=5/10/15/20/25: N×2 алмазов, N×4 камней, N материалов, N/5 зелий, N/5 эликсиров плюс прежние билеты. Задание i=1/2/3: 5i камней, 2i материалов и зелье плюс билеты. Предложение i=1/2/3: 3i алмазов и эликсир плюс билеты. Условия открытия прежние, все наборы однократны до смены события.

Эти количества — явный тестовый баланс реализации. В доступном контексте нет исходного предыдущего ТЗ, поэтому совпадение с его точными числами или платёжными/рекламными сценариями не утверждается. Здесь используются настоящие типы TERRITORY, а не чужие предметы с фотографий.

Зелье здоровья совпадает с shop_potion_hp: potion/common, hp +50 instant. Эликсир силы совпадает с shop_elixir_atk: elixir/rare, attack +10 battle. При получении канонический совпадающий предмет складывается с существующим стеком; остальные предметы не меняются.

Неиспользованные ресурсы сохраняются в `monopoly_v2.pending_rewards`, в том числе после смены 72-часового события. Finish/повторные claims не дублируют ресурсы. Отдельный `territory_monopoly_claim_v2` сверяет точный snapshot и updated_at, атомарно зачисляет накопленное и очищает только собственный ledger. При ошибке всё откатывается. Клиент сохраняет текущий прогресс до получения; после успешного подтверждения перезапускает загрузку игры, поэтому общий cloud/actions код и кеши версий не приходится изменять. Золото остаётся в существующем pending_gold и использует прежнюю выдачу зала; его лимит 1000/сутки не изменён. Красные алмазы не затрагиваются.

## Почему падает test:mobile-home

В main `f5b00cd2e3646712afaaa78bf64683d2d6fcc97b` отсутствует `public/city-bg-vibrant.webp`. Коммит удаления — отдельный коммит main, он не входит в изменения Монополии. Тест `scripts/check-mobile-home-ui.mjs` (blob `5dbf7b850f6f632753e871c980d02c2d3e7f7757`) требует этот файл строкой access(). Исходники и тест не изменены в PR #36. GitHub run 39021375834 упал именно на `npm run test:mobile-home`; отдельный запуск неизменённого теста с файлами main воспроизвёл ENOENT того же пути.

### Предложение безопасного исправления

Отдельный **asset-only PR**, с отдельным согласованием владельца: восстановить ровно утверждённый `public/city-bg-vibrant.webp` из последнего коммита до удаления `6183b237a6b93245a16d23f5ded71e6b0714eb1f`. Не менять HomeScreen, App, CSS, админку, скрытый вход или сам тест; не подставлять случайную картинку/пустой файл и не ставить continue-on-error. После восстановления проверить SHA исходного ресурса, test:mobile-home и ручной вид города. Это только предложение, **в текущей ветке файл города не восстановлен**.

В main были удалены и другие общие растровые ресурсы. Возврат одного city-bg-vibrant исправит конкретный assert, но не доказывает исправность всей городской графики. Полный разбор удалений — отдельная работа с отдельным согласованием. Четыре ресурса Монополии уже изолированы в public/monopoly и от этой ошибки не зависят.

SQL остаётся неподтверждённым кандидатом `supabase/staged/territory_monopoly_v2.sql`. Ничего не установлено, main не менялся, игра не публиковалась. Браузер, Android Telegram, staging end-to-end и настоящая конкурентная сеть всё ещё не проверены.
