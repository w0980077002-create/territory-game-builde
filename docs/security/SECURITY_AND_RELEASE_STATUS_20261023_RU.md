### Текущая критическая граница
`src/game/cloud.ts` всё ещё делает полный CAS UPDATE `players.game_state`, золота и алмазов с клиента.
RLS ограничивает строку игроком, SQL-триггеры защищают согласованность; они не доказывают происхождение каждой награды. Полностью server-authoritative экономика **не реализована**.

### Безопасное продолжение
1. Полная внешняя резервная копия PostgreSQL и проверка восстановления на отдельной базе (сейчас нет подтверждения).
2. Серверные транзакции для PvE, заданий, ежедневных наград, покупок и ремесла; `operation_id` для идемпотентности, серверные каталоги цен и наград.
3. Старые аккаунты, VIP, экипировку и историю не сбрасывать. Тесты двух устройств/сетевых сбоев.
4. Лишь после миграции клиента можно отозвать прямые `INSERT/UPDATE` на критические колонки. Резкий REVOKE сейчас сломает сохранения.
5. Административные блокировки остаются ручными; не включать реальные денежные выплаты до полной защиты.

Эти файлы не являются миграцией production и не объявляют игру финансово безопасной.

### Удалены исторические установщики
Четыре workflow старой ZIP/Bolt-цепочки с правом перезаписи основного кода удалены. История GitHub сохраняет их исходники; действующая игра использует прямые коммиты и единый gated Pages publisher.
