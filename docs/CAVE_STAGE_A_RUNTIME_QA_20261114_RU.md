# Тёмная пещера — проверенный участок этапа A, draft

Основание: #314, #520, #521, `TERRITORY_OWNER_DECISIONS_20261114_RU.md` со свежими дополнениями `ad487ce` и тестовый баланс v1. **Это отчёт об изменениях ветки, не новое ТЗ и не заявление о завершении A/B/C. Production не изменён.**

## Что реализовано

- `ServerAdventureScreen` использует живую Canvas-сцену из существующих оригинальных фонов и поз героя/противника. Сохранены выбранный облик, текущий спутник, каталог 100 этажей и серверный `start/advance/resume`. Попадания и числа урона берутся из квитанций; повторная доставка событий не создаёт новых попаданий.
- Родные семь нижних направлений остаются доступны между подтверждёнными операциями. Возврат в Бой сохраняет выбранную Пещеру. При переходе из Испытаний, Похода и настоящего `MapScreen` восстанавливается тот же `session_id`, баланс и этаж.
- Начальный экран больше не выбирается по случайному наличию локального ключа: по умолчанию открываются серверные этажи. **Кандидат единого меню** включается через `VITE_CAVE_UNIFIED_UI=true` в изолированной сборке. По умолчанию флаг выключен: действующий переключатель и DEMO сохранены до мобильной приёмки владельца, как требует #314. Исходники и автономные тесты DEMO не удалены.
- Новый серверный режим времени включается только для новых `adventure_v1_stage_*` с явно установленным сервером `rules.caveActiveClock=true`. Старые попытки сохраняют прежний договор времени. Пауза/продолжение/×1/×2 — ревизионные команды через существующий журнал операций, а не смена надписи на клиенте. Фоновое время не догоняется часами: активный шаг ограничен 1100 мс до множителя скорости.
- Семь ячеек пояса и семь обычных слотов сохранены. Пояс открыт сразу, экипировка — отдельная раскрываемая панель; на малой высоте панели прокручиваются внутри HUD. Никаких 12 Umbra-слотов на боевой сцене.
- Подготовлен staged-контракт реального использования подтверждённых доз: HP/атака/защита/крит используют действующие эффекты PvE. Применение меняет бой, списывает одну дозу, обновляет источник и CAS-квитанцию **в одной транзакции**. Начальный запас закреплён за попыткой, максимум пять одинаковых; повтор запроса ничего не списывает повторно. Подмена/пополнение сохранённого слота не даёт новых доз текущему бою.
- Автозелья включаются отдельно, по умолчанию OFF; применяют имеющееся подтверждённое HP-зелье при HP ≤35%, в том числе при выключенном Auto-бое. На неподдерживаемом сервере пояс честно остаётся доступен для просмотра без списаний.

Новая SQL-заготовка не заполняет аттестации из редактируемого `game_state`, не выдаёт зелья и не включает боевой режим. Она не добавлена в production migrations. Проверен откат при неожиданном изменении кошелька старым save-триггером. Обычные и тёмные камни, синие/красные алмазы и награды других режимов не менялись.

## Как воспроизвести без аккаунта и production

```sh
npm run preview:cave-runtime
# В отдельном терминале:
python scripts/check-cave-runtime-browser.py
```

Открыть `http://127.0.0.1:4178/`. Это **настоящие** `BattleScreen`, `MapScreen`, `ServerAdventureScreen`, адаптер квитанций, облачная CAS-очередь, боевой service/engine и staged SQL в **временной локальной PGlite**. Подменены личность, сетевой транспорт Supabase и не используемый здесь классический `PveFight`; соседний Инвентарь в оболочке — тестовая точка перехода. Семикнопочная навигация оболочки воспроизводит native-nav композицию; весь `App` с Telegram-авторизацией этим harness не запускается. Данные синтетические, сервер слушает только localhost, внешние запросы в браузерном сценарии запрещены проверкой. Перезапуск процесса создаёт чистую **тестовую** базу.

Для снимка «до»: `node scripts/serve-cave-runtime-preview.mjs --before` загружает исходный `ServerAdventureScreen` из `ad487ce`, сохраняя те же тестовые данные и оболочку. Не запускать оба процесса на одном порту. Сгенерированный HTML в `artifacts/cave-runtime/` не коммитится.

## Что остаётся до полного этапа A и выпуска

1. **Это пока одна серверная встреча на этаж.** Многокомнатные волны и два выбора порталов из DEMO ещё не включены в авторитетный run-контракт. Не выдавать эту сцену за полную экспедицию.
2. Спутник следует за героем визуально. Новые серверные удары/лечение спутников не имитируются; требуется отдельный проверенный источник их способностей. Новые персонажи из PR #491 не импортировались повторно.
3. Прямая реальная выдача Umbra/самоцветов, новый кошелёк усиления и этапы B/C ещё не реализованы здесь. Существующая локальная «Тестовая добыча» остаётся маркированной песочницей, а не поддельной серверной наградой. Настоящие золото/XP приходят только из settlement.
4. Смена времени и расход пояса требуют проверки на отдельном PostgreSQL/Supabase staging со сверкой фактических функций/триггеров и происхождения доз. Edge Function и staged SQL в production **не развёрнуты**. Старые профили, кошельки и попытки не переписывались.
5. **Физический Android и Telegram WebView не проверены.** Мобильная приёмка владельца обязательна до замены обычного меню, как прямо требует #314. Запрос публичной Pages-страницы из окружения получил HTTP 403; опубликованный SHA и авторизованные production-маршруты не подтверждены.

PR остаётся draft и не закрывает #314. Этапы B/C не начинались под видом завершённого A. Нет merge, Pages deploy, auto-merge, production SQL, платежей или изменений живых аккаунтов.
