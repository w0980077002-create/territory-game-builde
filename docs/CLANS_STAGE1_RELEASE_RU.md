# Кланы: пакет завершения этапа 1

## Реализовано и проверено локально

Существующий интерфейс сопоставлен с фактическим SQL-контрактом: receipt кошелька, список участников, здания, босс, личный вклад в задания, чат и война. Создание стоит утверждённые 30 красных алмазов, с 15 уровня; золото не списывается. Покупка блокирует игрока и существующий защищённый кошелёк лицензии мастера, использует минимум его баланса и HUD-зеркала, списывает обе записи; клиентский JSON не может увеличить доступный баланс. Отсутствующий защищённый кошелёк блокирует покупку, повторного seed из сохранений нет. Взносы материалов проверяют сроки и соответствие партий числовому остатку и расходуют сначала партию с ближайшим сроком; просроченные/несогласованные сохранения требуют обновления перед взносом. Доступны поиск кланов, вступление/заявки, просмотр и обработка заявок руководством, поиск свободных игроков по имени и отправка приглашений, принятие приглашений, смена ролей и выход. Рейтинг доступен через видимую кнопку. Черновик сообщения сохраняется при ошибке отправки.

Исправлены ошибки SQL: сортировка JSON в каталоге; неверное соединение заявок с уже вступившими участниками; отсутствие ID нового кланового сезона; потеря награды убитого босса при открытии экрана; невозможный подсчёт двух недельных убийств из одной перезаписываемой строки босса. Урон не превышает оставшееся HP. При победе сервер сохраняет неизменяемые права каждого участника на рассчитанную награду в clan_boss_rewards до смены встречи. Следующий босс появляется сразу, независимо от неактивных участников. Старые заработанные награды показываются отдельным списком и получаются по номеру босса; их размер не пересчитывается при следующих боях и срока получения нет. Повторные награды запрещаются CAS и уникальными квитанциями с откатом всей транзакции.

Исправлен выход единственного лидера: раньше удалялась только запись `clans`, а участник оставался в `clan_members` и больше не мог вступить или создать новый клан. Теперь перед роспуском проверяются незабранные награды босса и активная клановая война; при наличии хотя бы одного блокера данные сохраняются, игрок видит понятную причину. После подтверждения сервер атомарно удаляет связанные записи клана и членство, не трогая личные сохранения и полученные награды. История завершённых войн и архив сезонов остаются; имя распущенного противника хранится в снимке войны. Клиент требует явного подтверждения роспуска, а лидер с участниками обязан передать руководство.

Подбор соперника для клановой войны сериализован транзакционной блокировкой, чтобы две одновременные заявки не создали пересекающиеся войны. PGlite теперь проходит реальное сведение двух кланов, запрет роспуска во время войны и сохранение имени соперника в завершённой истории.

## Установка — отдельный проверяемый инфраструктурный выпуск

В production не выполнялись изменения. По проверке владельца задачи на 26.10.2026 клановые таблицы/RPC отсутствуют; интерфейс нельзя объявлять работающим в production до установки.

Зависимость: уже установленный `territory_private.territory_master_license_red_wallet_v1` из проверенного выпуска лицензии мастера. Не выполнять повторный seed этого кошелька для установки кланов.

Проверяемый пакет: `supabase/staged/territory_stage1_clans_install.sql`.

Он устанавливает существующую клановую схему и функции одной транзакцией, не переписывает players и включает RLS на всех таблицах. Запись только через RPC; привилегии PUBLIC/anon сняты, authenticated получает явный список клиентских функций. Внутренние функции начисления XP, принудительного вступления и событий недоступны клиентам. Изменяющие состояние внешние функции проверяют действующего неблокированного игрока; операции босса и зданий проверяют членство, управление — роль.

Исторические файлы `20261017_clans_schema_v1.sql` и `20261017_clans_functions_snapshot.sql` остаются неизменными. Исправления роспуска и войн вынесены в `supabase/staged/territory_stage1_clans_hardening.sql`. `node scripts/clans/build-install.mjs` воспроизводимо объединяет историческую схему, функции, hardening и права доступа; `node scripts/clans/build-install.mjs --check` сверяет установленный staged-файл с результатом генерации без записи. При существующих клановых таблицах установка намеренно завершится ошибкой; для такой среды необходим отдельный diff, а не повторная установка.

## Проверки

`npm run test:clans` устанавливает **точный staged artifact** в PGlite и выполняет RPC под `SET LOCAL ROLE authenticated`. Проверяет цену, запрет повторного создания/дубликатов, CAS, взносы, сохранение кошелька, поиск, видимость заявок, вступление и роли, поиск приглашённых, приглашение/принятие/выход, неактивного участника с незабранной наградой → нового босса → получение старой награды → запрет повтора, сохранение награды после срока следующей встречи, чат после повторного открытия, заработанную награду задания и запрет повтора, запреты забаненных/посторонних, недоступность внутренних начислений, RLS и нормализацию ответа в фактическую клиентскую модель.

Дополнительно: `node scripts/check-clan-red-gem-price.mjs`, `npm run typecheck`, `npm run build`.

Production Telegram/Pages smoke-тест всего пути обязателен после reviewed установки. Автоматического production SQL/публикации этот пакет не выполняет.
