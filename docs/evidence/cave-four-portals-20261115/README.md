# Четыре портала — полный тестовый этаж

Основа main `8dd8c2b`; финальный игровой код `86480d8`, последующие коммиты содержат доказательства и расширение проверок draft PR #531. Все предметы, этажи и награды здесь **локальные тестовые**, не имущество аккаунта. Production не изменён.

## Реализовано

Существующий World — единственный источник состояния локальной попытки: `rules`, `floor`, `unlockedFloor`, `stars`, `room`, `wave`, враги/HP/спутники/босс/фазы, использованные зелья, результат. Перед каждым из четырёх участков выбирается одна из трёх видимых арок. Каждая зачистка состоит из трёх групп: 3 + 3 + 3/4/5 врагов. Всего 36–44 обычных противника, затем один существующий трёхфазный босс. Только его смерть открывает следующий локальный этаж; после 100-го нет 101-го.

Сохранены сцена, движение/камера/параллакс, контактные удары, спутники, звук/комиксные эффекты, Auto/автозелья/скорость/пауза, 12 Umbra + отдельные Крылья, семь зелий и семь нижних разделов. Новых персонажей и арта нет. Цвета и звёзды находятся непосредственно на арках, выбор подсвечивает арку и запускает прежний плавный переход.

Старые checkpoint без `rules` восстанавливаются как прежняя попытка. Новый старт после неё использует четыре участка. Старая механика остаётся исключительно для восстановления уже сохранённых попыток и регрессионной проверки, без нового пункта меню.

## Тестовый баланс и добыча

Конфигурация `DIFFICULTY` в `engine.ts` — предложение для личного баланса, **не утверждённая live-экономика**:

| Звёзды | Враги | HP | Атака | Делитель входящего урона врага | Броски существующей таблицы |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 9 | ×1 | ×1 | ×1 | 1 |
| 2 | 10 | ×1,12 | ×1,12 | ×1,04 | 2 |
| 3 | 11 | ×1,25 | ×1,25 | ×1,08 | 3 |

Проценты редкости не вводились: используются существующие `rollUmbraItem` / `rollRank`. На сложном участке выбирается лучший по рангу из дополнительных независимых бросков той же таблицы. Даже три звезды могут дать обычный предмет. После победы выдаются четыре находки участков и существующая пара предметов босса; у босса число бросков соответствует максимальному выбранному риску. Камни/гемы — существующий изолированный reducer, без новой валюты. Награды выдаются только после босса. Квитанции `floor-section:<runId>:<section>` и `expedition:<runId>` сохраняются отдельно от ограниченной истории обычных действий, поэтому сотни примерок не делают победу повторно оплачиваемой. В карточке предмета видно количество его копий; существующий защищённый разбор даёт только тестовые камни.

Весь checkpoint и тестовый склад используют прежние отдельные ключи, без чтения GameState или cloud save. Добыча живёт в существующем складе, связанном с попыткой долговечным runId/квитанциями. Восстановление частично записанного набора повторяет только недостающие операции.

## Архитектурный аудит и граница безопасности

`ServerAdventureScreen` / combatV1 service продолжают существующий single-encounter договор и могут возвращать настоящее settlement с XP/золотом. Он **не связан** с новой локальной победой. Не изменены ServerAdventureScreen, BattleScreen, App, combatV1, серверный каталог 100 этажей, SQL или RPC. Старые серверные попытки сохраняют свой путь восстановления. Два существующих входа не замаскированы переключением UI; это разрешённое владельцем завершение изолированного цикла до безопасной интеграции.

Повторно проверены #522 (`45c8ad4`) и #491 (`3dfc98b`): оба draft и конфликтуют с main. Фактические пересечения #522 — `package.json`, `renderer.ts`; он также меняет App/BattleScreen/ServerAdventureScreen/service/receipts/SQL и не содержит этот полный цикл. #491 пересекается с `CaveExpeditionPreview.tsx` и сборщиком, импортирует отдельный арт/просмотрщик.
