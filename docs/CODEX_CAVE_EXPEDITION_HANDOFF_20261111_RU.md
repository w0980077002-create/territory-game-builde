## 2. Визуальная композиция и качество
- Telegram Android WebView: ширины 320/360/390/430 CSS px, с шапкой и нижним навбаром. На первом экране без скролла видны главный персонаж, спутники, минимум два врага, важные HP, активная кнопка и энергия.
- Контроль масштаба: главный герой ясно отделён от спутников; враг появляется справа и подходит; босс значительно крупнее. Нельзя, чтобы верхние 50% поля боя были пустым порталом, а фигуры были раздавлены у нижнего борта.
- Анимация должна иметь реальные **состояния и кадры** (idle/run/attack/hit/death), тайминг воздействия и звук/эффекты по возможности; не продавать CSS-подпрыгивание одного `idle.webp` за анимированного врага.
- Минимум 3 действительно разных оригинальных cave-only противника и 1 особый босс для доказательного vertical slice; оригинальные фоны минимум двух биомов, новые эффекты каждой сцены. Потом масштабировать контент до остальных этажей.
- TERRITORY имеет свой стиль: старый тёмный дуб с натуральными волокнами, золотая ковка, верёвки где конструктивно уместны, выразительные локальные эффекты биомов. Не делать всё одинаковым фиолетовым. Только оригинальные, разрешённые для игры ассеты.

### Обязательная реализация длинного фона (уточнение владельца 11.11.2026)

**Фон должен выглядеть как длинный непрерывный путь, а НЕ одна неподвижная картинка, привязанная к экрану.** Принцип реализации — `tileable parallax side-scroller`:
- На каждую отдельную комнату/биом подготовить **2–4 независимо прокручиваемых слоя**: дальняя атмосфера и скалы (самый медленный), средние декорации, ближние объекты и **непрерывная линия земли** (скорость мира). Объекты героя/спутников/врагов — самостоятельные спрайты, не часть фона.
- Длинный маршрут собирать из **бесшовно стыкующихся горизонтальных сегментов** с повторением или чередованием деталей. Допустимы повторяемые тайлы либо соседние куски с проверенными переходами; нельзя единственный огромный фон на всю сцену, резкий шов, скачок камеры или пустой край при движении.
- Герой действительно движется вправо в игровых координатах; при следовании камеры удерживается в **левой трети видимой сцены**, дальние слои идут медленнее, ближние — быстрее. Эффект параллакса не должен подменять фактическое сближение героя с врагами или подход к выбранному порталу.
- Каждый из **двух порталов** после волны остаётся полностью виден и нажимаем. Выбор заставляет героя подойти именно к выбранной арке, затем переход меняет набор слоёв/биом и следующие группы врагов; смена комнаты не просто перекрашивает прежнюю.
- Оптимизировать для узкого Android Telegram WebView: не грузить длинную 10000px-картинку; использовать ограниченное количество текстур, responsive размер, повторное использование сегментов, независимую анимацию VFX, при необходимости снижать интенсивность частиц. Без заметных разрывов, подёргивания/плавающей земли, деформаций или неожиданного скачка игрока.
- В приложенном тесте и демонстрации обязательно показать **достаточно длинный бег вправо**, чтобы увидеть минимум два стыка сегментов, а также **смену биома при выборе портала**. Если сегментов и реального пролистывания пока нет, работу по фону не объявлять готовой.

**Временная последовательность и действия — именно живой игровой цикл:**
- Состояния `ENTER → RUN_RIGHT → WAVE_SPAWN → APPROACH → FIGHT → CLEAR → PORTAL_CHOICE → PORTAL_ENTER → NEXT_ROOM → BOSS → RESULT`. Выход, поражение, возврат, перезапуск, скрытая вкладка и отмена анимаций отдельно обработаны; не должно остаться двух одновременно работающих игровых циклов после переключения разделов.
- Персонажи имеют игровые мировые координаты `worldX`; камера — `cameraX`; визуальные позиции считаются как `worldX-cameraX`. У слоёв реальные, разные коэффициенты параллакса; спрайты/земля/враги/порталы находятся в согласованных мировых координатах. Не подменять бег панорамированием фоновой фотографии.
- Явная проверка сближения/дальности атаки и таймингов попадания. В режиме демо удары изменяют только демо-HP; анимация удара, VFX и цифра синхронизированы с одним игровым событием; `death` завершает конкретного врага, счётчик волны обновляется один раз. Не имитировать атаку исключительно случайными вспышками вне фактического движения. Для демо допустима детерминированная простая боевая формула: явно пометить её тестовой, не копировать реальные награды/шансы.
- **Автоматическое движение вперёд** при свободной дороге, остановка при врагах и при порталах; перед выбором портала — пауза, два отдельных действия касания (доступные пальцем). В ручном режиме действия/активные способности дают настоящий эффект на демо-врага; автоуправление остаётся отдельным видимым переключателем. Настройки и набор способностей не выдавать за подключённую серверную систему.
- В первом прототипе **ровно один демонстрационный маршрут из трёх последовательных комнат**, но после 1-й и 2-й — по две реальные ветви; любой из двух вариантов меняет хотя бы конфигурацию комнаты/врагов/фон в следующем сегменте. Последняя комната завершается крупным отдельным боссом. Предсказуемая повторяемость и два независимых прохождения обоих выборов — обязательны. В каждой боевой комнате несколько противников, не один.
- Полноценные оригинальные спрайты/кадры должны использовать разделение персонажа и фона, одинаковую точку опоры (ступни), согласованное направление взгляда, сопоставимый масштаб; минимум `idle`, `run`, `attack`, `hit`, `death` для героя, пещерных противников и босса. Не допускать, чтобы демонстрационный герой оказался нарисован не тем героем, который действительно есть у игрока. Для первого теста использовать выбранный внешний вид героя и реальные одобренные облики спутников, новые cave-only враги — оригинальные. Если отсутствуют необходимые кадры, создавать/встраивать их, а не заявлять «живой бой» по одному статичному изображению.

- Проверки: `npm ci`, `npm run typecheck`, `npm run build`, cave-specific tests и браузерные сценарии на всех 4 ширинах. Переходы портал-1/2, воспроизведение/повторный запуск, блокировка повторного лута, отсутствие live API calls, изоляция от чужих экранов.
- Принятие: **Codex код → независимая проверка ChatGPT → владелец играет на своём телефоне → доработки до одобрения → только после этого merge**. Зелёный CI не означает принятие.

## 5. Отчёт исполнителя
Ответь коротко: PR/commit; где именно реальный рабочий preview (или почему URL ещё не существует); как владелец воспроизводит 3 комнаты и 2 выбора; список новых enemy/boss art и поддерживаемых анимаций; тесты и неготовые части; подтверждение, что живая БД/камни/предметы не затронуты.

**Не ограничивайся планом. Приоритет — быстрое доказательство работающего side-scrolling забега с ПОРТАЛАМИ, а не большой рефакторинг сервера.**
