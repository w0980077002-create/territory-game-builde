# Недельные сезоны: проверяемый пакет

Сервер считает только подтверждённые победы из `arena_weekly_wins_v1`: одна победа — одно очко. Неделя начинается и заканчивается в воскресенье в 00:00 Europe/Kyiv с учётом перехода на летнее/зимнее время. Равные результаты упорядочиваются по времени последней победы и UUID, без изменяемого рейтинга из сохранения. Участвуют незаблокированные аккаунты с подтверждённым Telegram.

Владелец утвердил призы 26.10.2026:

| Место | Золото | Синие алмазы |
| --- | ---: | ---: |
| 1 | 3000 | 90 |
| 2 | 2000 | 65 |
| 3 | 1500 | 45 |
| 4–5 | 1000 | 30 |
| 6–10 | 500 | 15 |

`territory_weekly_seasons_v1.sql` — подготовленный SQL. Тик закрывает завершённые сезоны, сохраняет результаты и создаёт настоящие письма с наградами в одной транзакции. Блокировка и отметка завершения защищают от повторной рассылки. Получение письма использует существующую атомарную `territory_admin_claim_grant_v2`; нового клиентского начисления нет. Награды и имя победителя сохраняются в истории. Каталог наград копируется в сезон при открытии и не меняет прошлые обещания.

Порядок согласованной установки: проверить существующие `arena_weekly_wins_v1` и атомарную почту v2; установить `territory_weekly_seasons_v1.sql`, `territory_weekly_seasons_admin_v1.sql`, обновлённую Edge Function `admin-api`; установить `territory_weekly_seasons_cron_v1.sql`; применить `territory_weekly_seasons_activate_v1.sql` с утверждёнными призами. Сам базовый SQL выключен до явной активации. Повтор активации не перезаписывает позднейшие изменения владельца.

Задание cron запускается раз в минуту, закрывает завершившийся сезон и открывает текущую календарную неделю. Оно не выдаёт призы за исторические недели, для которых сезон не создавался; при сбое восстанавливает закрытие уже созданных сезонов. Старые победы/балансы/инвентарь не переписываются. Проверить после установки: cron присутствует и активен, серверный статус показывает сезон и десять призовых мест, реальная почта выдаёт награду однократно.

В существующей админке добавлена вкладка «Недельный чемпионат». Владелец меняет награды **следующих сезонов** через прежнюю серверную проверку администраторского токена. Публичные роли не имеют доступа к конфигурации и управляющим RPC: ими пользуется только существующая Edge Function с `service_role`. SQL валидирует валюты и суммы, проверяет версию конфигурации, сохраняет квитанцию запроса и аудит в одной транзакции. Другая вкладка не может незаметно перезаписать свежую конфигурацию. Вход пятью нажатиями и пароль не изменены.

Клиент показывает активность, серверный таймер, призовые места, проверенный рейтинг и историю. Обновляет данные раз в минуту; устаревший ответ после смены аккаунта игнорируется. При отсутствии серверного RPC остаётся честный экран подготовки.

Проверки:

- `node scripts/check-weekly-seasons.mjs`: отдельная PGlite, реальные SQL атомарного получения почты v2 и триггера защищённого красного кошелька; все десять призовых мест и места 11–12 без призов; закрытие, повтор без дублей, откат частичной рассылки, сохранённые кошелёк/game_state и новая версия сохранения, чужой аккаунт, история, следующая неделя, редактирование будущих призов, CAS/идемпотентность/аудит, ACL, переходы DST 167/169 часов.
- `node scripts/check-season-admin-api.mjs`: существующий Edge handler и настоящая HMAC-проверка с тестовым секретом; отказ без сессии/с поддельной подписью, правильный вызов серверных RPC, отказ для некорректных наград, конфликт версии и недоступный backend.

Эти локальные тесты не заменяют проверку фактической установки SQL/Edge/cron и Pages после согласованной публикации. Production этот пакет сам по себе не изменяет.
