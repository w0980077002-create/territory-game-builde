# Пещера — WOW-подача (визуальный этап)

> Только клиентская подача существующей Тёмной пещеры. Движок боя, баланс, RNG, HP/урон/скорости, четыре участка, босс, 100 этажей, награды, RPC status/start/finish, SQL и сохранения **не менялись**. Правила работы: [AGENTS.md](../AGENTS.md).

## Контракт подачи

- Всё — чистая функция состояния мира (`effect.born`, `enemy.deathAt`, `phaseAt`…), частицы заданы формулой от возраста. Пауза и перезагрузка дают тот же кадр; `StageMemory` помнит только момент смены фазы и место гибели босса.
- Нет `Math.random`, таймеров и вызовов движка в `src/components/pve/cavePreview/*`. Проверяется `scripts/check-cave-wow.mjs` (в составе `npm run test:cave-expedition`): одинаковый исход засеянного этажа с подачей и без неё.
- Reduced motion: без тряски, вылетов, вспышек и анимации финала; сигналы опасности остаются статичными.
- Low-уровень visual budget отключает тень босса, ореолы и часть частиц.

## Проверки

`npm run test:cave-expedition`, `npm run test:cave-expedition:browser`, `npm run test:cave-animation:browser`, `python scripts/check-cave-wow-browser.py` (320/360/390/430, RU/EN, пауза, перезагрузка, reduced motion, окно победы).

Производительность измерена только в Chromium с программной отрисовкой и 4× замедлением CPU (360×640, DPR 2): бой в районе — на уровне прежнего, бой с боссом — примерно на 15–20 % кадров меньше прежнего. **Физический Android/Telegram WebView не измерялся.**
