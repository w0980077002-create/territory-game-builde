# TERRITORY 1.0: многослойный бой

Подготовлены два настоящих cutout-рига по существующей утверждённой графике:

- **Викинг `heroes/male_viking` (внешность m2)** — в том числе зеркальный противник в PvP.
- **Гоблин `enemies/goblin`** — существующий гоблин-разведчик PvE.

У каждого отдельно двигаются торс, голова, плечи, предплечья, бёдра, колени, кисть с оружием, кисть со щитом и нижняя часть бороды/кос. Меч находится внутри иерархии правого предплечья, щит — левого. Области локтей и коленей перекрываются; суставы не оставляют отверстий. Координаты нормализованы вправо; вся иерархия противника зеркалится один раз. Герой сохраняет синий костюм, крылатый шлем, золотую бороду, деревянный щит и меч; гоблин — зелёную кожу, красный гребень, шипованную броню и изогнутый клинок.

Воспроизводятся дыхание и перенос веса, рубящий удар, выпад, удар сверху, усиленный замах подтверждённого крита, блок с отдачей щита, уклонение, обычное и критическое попадание, поднятие оружия после победы и опускание на колени после поражения. Все боевые действия возвращаются в стойку; конечные позы остаются видимыми. Падение и победная поза начинаются после снятия последнего события персонажа из очереди: ранний PvP-снимок нулевого HP не вызывает падение и последующее возвращение в стойку посреди подтверждённых ударов. Удаление события из очереди не перезапускает падение.

## Что осталось на прежней отрисовке

`male_rogue`, `female_warrior`, `female_archer`; кабан, разбойник, волк и тролль; **все боссы**, включая Стража испытаний; **все спутники**. Для них нет подготовленных и проверенных независимых слоёв. Они сохраняют собственные утверждённые изображения поз, прежние движения и эффекты. Их нельзя считать скелетно анимированными. Отсутствующий/повреждённый файл нового рига также оставляет персонажа на этой системе, а не делает его невидимым.

## Устройство

`FighterFigure` выбирает риг по фактическому `combatFrames.idle`, предварительно декодирует восемь WebP частей, включает риг между ударами (без позднего повторного замаха при медленной загрузке) и использует общий `SkeletalFighter`. Этот путь уже используется `BattleScene` и `PveFight`, включая испытания. Отдельного движка или production demo-route нет.

События берутся из существующих `StrikeEvent`. Контакт — **350 мс**, как существующее обновление HP в PvE; движение — 810 мс, внутри прежних окон 870/920 мс. В x2 эти длительности делятся на два. Скорость текущего раунда и конечной анимации фиксируется, чтобы переключение x1/x2 не сдвигало контакт и не перезапускало поражение. Победа PvP берётся из результата сервера, а не из анимации. Баланс, результаты, прогресс и сетевые протоколы не меняются.

Web Animations API изменяет локальные трансформации SVG, CSS управляет спокойным ожиданием. Покадровых React-перерисовок нет. Анимации, таймер завершения и слушатель reduced motion освобождаются при размонтировании. При reduced motion остаётся спокойная конечная поза и короткая надпись; крупные перемещения отключены.

След расположен непосредственно на клинке. Щит получает собственный отблеск. Пыль, искры, вспышка, критическая волна и победные частицы имеют конечную длительность и фиксированную сложность. При малом числе процессорных потоков либо шести медленных кадрах во время короткой начальной выборки убираются дополнительные частицы/кольца. Центральный дублирующий `CombatClash` заменён эффектами бойцов; он не закрывает движение оружия. Никакие эффекты не создают ударов и не меняют HP.

## Графика и воспроизведение

В репозитории сохранены исходный атлас `docs/art-reference/combat2d/cutout-source.png` и экспортированные части `public/assets/territory/combat2d/`. Атлас подготовлен по двум существующим idle.webp с дорисовкой скрытых поверхностей и закрытых суставов. Это новые отдельные детали по утверждённому дизайну, а не прямоугольные обрезки цельного бойца. Небольшие маски экспорта исключают соседние детали атласа из прозрачных промежутков. В браузере нет генерации изображений, внешних API или платных библиотек.

Повторный экспорт (ImageMagick, локально):

```sh
node scripts/extract-combat-rig.mjs
bash /tmp/extract-combat-rig.sh
```

Проверки:

```sh
npm run typecheck
npm run build
npm run test:combat
npm run test:pve
npm run test:combat:browser
```

Последняя команда требует бесплатные Python Playwright и Chromium в среде проверки. Она собирает настоящие production-компоненты с изолированным состоянием в `/tmp`, блокирует внешнюю сеть и проверяет независимые суставы, атаки/реакции, сроки эффектов, зеркалирование, окончание боя, x2, reduced motion, отключение анимаций и реальные элементы управления PvP/PvE/испытаний при 360/390 px. Состояние реальных игроков не используется. PNG и JSON-отчёт сохраняются в `/tmp/territory-combat-verification/`.

Измерения rAF в headless Chromium характеризуют только эту среду. Они не подтверждают 60 FPS на физическом Android/iPhone. Telegram-авторизация и настоящий сетевой PvP здесь не проверены.

## Зафиксированный результат проверки 29.10.2026

TypeScript, production build, `test:combat`, `test:pve` и полный локальный набор регрессий review-ci прошли. Финальная браузерная проверка также прошла: ошибок JavaScript и отсутствующих игровых ассетов нет; намеренно отсутствующий файл рига корректно оставляет старый рендер. Проверена сохранность уже начавшегося падения при снятии последнего события. При x2 длительность каждой из 14 анимируемых частей составляет 405 мс. Отчёт содержит замер кадров атаки, а не только ожидания.

Сохранены [отчёт](art-reference/combat2d/verification.json), [контакт в PvP](art-reference/combat2d/arena-contact-390.png), [контакт в PvE](art-reference/combat2d/pve-contact-390.png) и [смешанный бой с прежним боссом испытания](art-reference/combat2d/trial-contact-360.png). Это снимки реальных компонентов с изолированным тестовым состоянием; сетевые результаты PvP не подменялись и не проверялись.
