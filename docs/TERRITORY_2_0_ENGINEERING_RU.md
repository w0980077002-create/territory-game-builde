# TERRITORY 2.0 — техническая карта перехода (рабочая ветка)

Дата: 2026-10-24. Статус: подготовительный аудит и контракт интерфейса, не релиз.

## A. Проверенное состояние репозитория
- `src/App.tsx` — React GameShell, текущий экран `city` по умолчанию, семипунктовая нижняя навигация и lazy imports. Здесь потребуется отдельная V2-оболочка; нельзя механически переписать главную ветку.
- `src/components/HomeScreen.tsx` — город и HUD, XP, HP/energy orbs, экипировка, боковые кнопки и переход в бой; UI следует переиспользовать выборочно, заменив композицию.
- `src/components/BattleScreen.tsx` — поход/испытания с затратой боевых камней на запуск. Непрерывный поход нуждается в другой модели с серверно утверждёнными наградами.
- `src/components/InventoryScreen.tsx`, `ProfileScreen.tsx` — текущие предметы/спутники/профиль; будущие V2-экраны должны использовать общие состояния через адаптер без потери старых данных.
- `src/game/types.ts` — сохранения GameState: уровень, XP, золото, синие/красные алмазы, HP, энергия, экипировка, инвентарь, главы, спутники, квесты и т. д.
- `src/game/cloud.ts` — загрузка/слияние сохранений, работа с wallet/save revision, миграции. Не переписывать без регрессионных тестов.
- `public/assets/territory/characters/` — имеющиеся изображения и отдельные анимации героев, врагов, боссов и спутников. Использовать как совместимые временные ассеты, затем заменять утверждёнными рисунками.
- `vite.config.ts` — GitHub Pages base связан со старым репозиторием, поэтому ветка сама по себе НЕ создаёт отдельный сайт.

## B. Границы и правила
1. Все V2-изменения в `territory-2.0`, `main` не трогать.
2. Начальный прототип должен использовать локальные демонстрационные данные, без начислений и сетевых мутаций, пока не готов staging.
3. Для реальной V2-экономики нужен **отдельный Supabase staging** и проверенный самостоятельный preview URL. Нельзя направлять новый клиент с изменёнными экономическими правилами в действующий Supabase.
4. Архитектура: presentation (HUD, экраны) → adapter (чтение состояния) → domain (боевой расчёт) → verified server operations (начисления и ресурсы). Нельзя вызывать выплату дропа из анимации.
5. Не копировать исходники, изображения, музыку, брендинг и тексты других игр. Привычный паттерн расположения элементов реализовать собственными иконками и ассетами TERRITORY.

## C. Первый крупный пакет: работающий V2-экран
**Критерии приёмки:**
- Сверху игровой профиль, VIP, голд/алмазы; никаких дублирующих полос энергии в правом верхнем углу.
- Слева компактные кнопки Задания, События, Друзья, Награды. Справа раскрываемое меню и небольшое число подходящих быстродоступных кнопок.
- В центре глава + прогресс боя; герой и взрослые спутники слева, враги справа. Герой движется вправо, враги идут ему навстречу и обращены влево.
- Фоны — бесшовные горизонтальные сцены, меняются с локацией; не отнимать место у боевой зоны.
- Красный круг HP слева, зелёная полоса HP с текущим/максимальным значением, уровень героя; голубой круг энергии/магии справа. **Арена над голубым кругом** (не AUTO).
- Ниже поля боя постоянно видна экипировка; под ней задание и действия x2/повтор.
- Внизу одинаковые второстепенные кнопки **Порт — Навыки — [центральный бой] — Приключение — Магазин**.
- 320–430 px мобильная ширина, без пересечений и без прокрутки главного HUD; safe area Android/iOS Telegram Mini App.
- В mock режиме любые награды декоративные и не влияют на игрока. Никаких запросов к production DB.

## D. Последовательность реализаций
1. **Слой V2 и маршрутизация:** отдельные компоненты для шапки, сцены, HP/энергии, экипировки, квеста, боковых кнопок и нижней навигации. Отдельный путь preview; текущий shell не переписывать, пока нет теста.
2. **Боевые состояния и анимации:** движение вправо, появление волн, анимации hit/block/dodge, мини-боссы и boss; выключаемые эффекты, 30/60 fps по возможностям устройства.
3. **Экономика:** подробная модель обычного фарма (без постоянных боевых камней), награды за этапы и лимитные режимы; обязательная серверная авторизация, rate limits, идемпотентность.
4. **Герой и склад:** экраны Снаряжение/Навыки/Руны/Последователи/Склад, сравнение вещей, шаблоны сборок, рецепты без потери существующих 7 слотов.
5. **Спутники:** старые ID и прокачку сохранить, новые ауры/звёзды вести расширяемыми полями; боевую корову сделать взрослым спутником, а не детским питомцем.
6. **Приключения/мир:** главы, элита, локации, отдельные боссы, шахты, экспедиции, кланы.
7. **Существующие возможности:** арена/чат, игровой зал, админка и профессии — сохранить и интегрировать в V2.
8. **Тестирование:** перенос сохранений; VIP/кошельки; замороженный прогресс; аномалии начислений; работа на слабом Android и на iOS; перезапуск Telegram WebView; откат.

## E. Правила выпуска
- Сначала статичный mock → затем функциональный V2 без монетизации → затем staging economy.
- Перед продакшеном: резервные копии, сухой прогон миграции, smoke + unit/economy + UI тесты, closed beta.
- Переключение игроков только после отдельного решения, без сброса прогресса, VIP, валют, экипировки, спутников.
- Логи/сигналы подозрительных действий для владельца, ручное решение о бане.
- Не трогать скрытый вход, пароли, правила админки и старый Telegram-бот.
