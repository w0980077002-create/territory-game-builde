# TERRITORY 1.0 — единый план доведения беты до выпуска

**Решение владельца: 30.10.2026.** Этот файл — единая точка правды о приоритетах. Исполнительская очередь и критерии готовности: [CODEX_QUEUE_RU.md](CODEX_QUEUE_RU.md). Общие правила для агентов: [AGENTS.md](../../AGENTS.md).

## Цель продукта
Существующая TERRITORY 1.0 уже доступна тестировщикам (около 100 зарегистрированных игроков). Наша задача — не пересоздать игру и не собирать бесконечные лабораторные PR, а закончить **полный игровой цикл** и затем объявить открытый запуск. Основа: герой становится сильнее в **Походе**, **Тёмной пещере**, через добычу экипировки, руны, кузницу и профессии; **Арена** показывает достигнутую силу. Сессия должна быть полезной и за 15–20 минут, и за длительный заход. Сложный необязательный функционал временно скрывать, а не выдавать за работающий.

## Однозначное решение по инфраструктуре
- **Единственная публикация игры: GitHub Pages**, репозиторий `w0980077002-create/territory-game-builde`, ветка `main`, workflow `.github/workflows/pages.yml`. Проверять ещё и `.github/workflows/verify-published-pages.yml`. Итоговая проверка — версия на опубликованном Pages и, когда нужен реальный Telegram WebView, целевой smoke.
- **Vercel сейчас не входит в процесс разработки и релиза.** Не создавать ради плана новые Vercel-сборки, проекты, подключение, релизные проверки или оплачиваемые услуги. Существующие проекты не удалять и не изменять без отдельного решения. Предпросмотр — локальная/browser-сборка или GitHub Actions. Возвращаться к Vercel лишь при конкретной технической необходимости и решении владельца, не по счётчику игроков.
- Рабочая Supabase определяется **по фактическому Pages workflow**, на 30.10.2026 это project ref `wmyrdpbwlkzsktnhookx`. Не выбирать одноимённую другую базу. Нельзя менять живую БД, политики, RPC, Edge или данные без отдельного безопасного задания, проверок и согласованного выпуска.
- Никаких новых платных инструментов. Отдельный TERRITORY 2.0 не трогать.

## Неизменные требования
- Сохранять всех тестировщиков и их прогресс, уровни, экипировку, алмазы, VIP, навыки и награды. Никаких wipe, пересоздания или «пустого» переноса.
- Скрытый вход в админку (пять нажатий «прогресс сохранён») не менять.
- Визуальный стиль: яркие мультяшные викинги, фактурное тёплое дерево, золотые элементы, утверждённые арты. Главный герой смотрит вправо, враг — влево; мобильная читабельность обязательна.
- Защищённые награды/камни/кошелёк — только авторитетным серверным ответом; повторы операции не должны давать двойную награду.
- Старые рабочие механики не ломать ради новой. Преждевременно включённые неполные второстепенные разделы допускается скрывать **без удаления данных**.

## Управление исполнением
1. Прежде чем начинать, читать этот план, [очередь](CODEX_QUEUE_RU.md) и `AGENTS.md`; сопоставить с актуальными issue/PR, чтобы не дублировать работу.
2. **Одна первоочередная вертикальная задача до готового результата.** Параллельная задача допустима только при явно непересекающихся файлах, состоянии и выпуске. Каждый PR: цель, изменённые файлы, тесты, нерешённые блокеры и план отката.
3. После слияния — подтвердить **успешный Pages deploy и опубликованный SHA**; отсутствие публикации = «код готов, ещё не доступен игрокам». Реальный Telegram smoke отмечать честно, не подменять симулятором.
4. Если упёрлись в недоказуемое владение/действительно рискованный серверный переход — безопасно оставить feature off, оформить точный blocker и продолжить независимую задачу из очереди. Не создавать циклы новых аудитов без решения проблемы.
5. Никакой GitHub-файл сам по себе **не запускает Codex автоматически**: это постоянное письменное ТЗ для запущенного агента или следующего рабочего сеанса. Не выдавать подготовленную очередь за выполненный код.
