# TERRITORY 1.0 — договор о работе команды и выпуске результата

**Дата решения: 30 октября 2026.** Применяется к `w0980077002-create/territory-game-builde` (TERRITORY **1.0**); основан на [плане](PLAN_RU.md), [очереди Codex](CODEX_QUEUE_RU.md) и [правилах агентов](../../AGENTS.md). Если есть противоречие, защита существующих игроков и подтверждённые решения владельца имеют приоритет.

## Что считаем успехом
**Не число коммитов и не отчёты.** Каждое завершённое задание — законченное действие игрока в реально опубликованной игре: путь по кнопкам → серверно подтверждённый результат → сохранение → возможность повторить. Технический прогресс без публикации помечаем «в разработке», а не «готово». Владелец не должен ежедневно тестировать наш код вместо команды.

## Ответственность
| Кто | За что отвечает | Что НЕ следует утверждать |
|---|---|---|
| **ChatGPT — координация, интеграция, контроль качества** | Устанавливает порядок по очереди, проверяет GitHub/PR/CI, распределяет непересекающиеся задачи, может делать доступные изменения в коде и документации, ревью, подготовку и безопасный выпуск через GitHub Pages, фиксирует опубликованный SHA и ожидаемый пользовательский результат. | Не является постоянно запущенным серверным процессом и не может гарантировать фоновое кодирование между сеансами без реально включённой автоматизации. |
| **Codex — инженер игровых механик** | При фактическом запуске получает одно ограниченное ТЗ, начинает с `#125 / draft PR #128`, делает серверные бои, тесты, восстановление, гарантии наград и предметов. На новых задачах — один законченный функциональный блок. | Issue/файл/PR сами по себе не запускают Codex. Не считать Codex работающим по одному названию исполнителя. |
| **Terra — мобильный интерфейс и визуал** | При фактическом запуске ведёт `#126`, адаптацию, анимацию и читаемость на телефонах по утверждённому стилю. Не редактирует те же файлы одновременно с Codex. | Назначение в документах не является подтверждённым автозапуском Terra. |
| **GitHub Actions + проверка по расписанию** | CI проверяет код/сборку, Pages публикует согласованное содержимое `main`; включённая автоматизация ChatGPT периодически проверяет очередь, может продвигать доступную безопасную работу и сообщает о существенном результате/блокере. | Не подменяет постоянную деятельность агента и не гарантирует самостоятельные исправления всех проблем. |
| **Владелец игры** | Решения только по новому платному сервису, риску для данных/экономики, спорному геймдизайну, неутверждённому стилю или финальной приёмке публичного запуска. | Не должен вручную проверять каждую кнопку или раздавать задания ежедневно. |

## Порядок: один готовый результат за другим
1. **C1 / P0: Пещера, серверные бои и сохранения.** `#125` и существующий draft `#128` — главные; обычный Поход и Испытания не смешивать с Пещерой. Риск legacy-владения, предметов пояса и атомарных эликсиров устранять доказательно; если нет безопасного решения, отключить только неподтверждённую часть и не выпускать ложную награду.
2. **C2 / P0 UI: мобильная Пещера.** `#126`; использовать независимые файлы или ждать завершения конфликтующей части C1, не начинать новый несовместимый PR.
3. **C3 / P1: путь героя 15–20 минут.** Домашняя цель → Поход → награда → инвентарь/сравнение → усиление → следующий бой → Пещера. Отдельный issue, не запускать одновременно с блокирующим C1.
4. **C4 / P1: руны, экипировка, профессии и кузница.** Включать только реальные эффекты, начиная с самых нужных для цикла героя; старые PR сначала перепроверить. Не складывать всё в один огромный PR.
5. **C5 / P2: Арена, сезоны, топ, награды/почта, ежедневное удержание.** После базового цикла, не сбрасывая баланс и прогресс.
6. **C6 / P3: подготовка к публичному запуску.** Мобильные проверки, длительная игра, сохранения/перезапуск, отсутствие двойной награды, опубликованный SHA, честное скрытие незавершённых второстепенных функций.

**Параллельно можно только независимую безопасную работу**: тесты, локальные фикстуры, UI без общих файлов/контрактов, read-only проверку релиза. Не делать десять новых PR ради «движения».

## Приёмка каждого задания — обязательный блок в PR / issue
- **Что увидит игрок:** конкретные кнопки, экран, результат и сценарий ошибки.
- **Код:** ссылка на PR, результат CI, tests (typecheck/build/релевантные integration/economy/mobile).
- **Публикация:** merge SHA, успешный Pages workflow и **проверенный опубликованный SHA**; если нет — «ещё не опубликовано».
- **Данные:** подтверждение отсутствия wipe, изменений VIP/алмазов/legacy экипировки; серверные действия — только авторитетно и однократно.
- **Верификация:** что проверено в настоящем Telegram, что только локальным браузером/симуляцией (не выдавать одно за другое).
- **Дальше:** один реальный блокер с ответственным либо следующая конкретная задача. Не создавать фиктивную «готовность».

## Правило самостоятельности и коммуникации
- В начале каждого рабочего запуска исполнитель читает [план](PLAN_RU.md), [очередь](CODEX_QUEUE_RU.md), [AGENTS.md](../../AGENTS.md), текущие PR/issue и продолжает **с последнего реально подтверждённого шага**, не переспрашивая уже решённое.
- Если задача безопасна и однозначна — выполнять, тестировать и фиксировать результат. Не отвлекать владельца промежуточными согласованиями или пустыми отчётами.
- Владелец получает сообщения **только** о реально опубликованной функции, объективном блокере с вариантами решения или вопросе, который без него нельзя решить.
- Если не хватает сведений о балансе/дизайне, сначала использовать уже утверждённые материалы. Когда действительно нужны решения владельца — собрать **короткий пакет конкретных вопросов с предлагаемыми вариантами**, не «15 вопросов ради 15 вопросов». Ответ записать здесь/в плане и не задавать повторно.
- Не объявлять «работаем непрерывно», если нет фактически запущенной задачи/автоматизации. У существующего расписания контроля максимум — периодическая итерация. Бесплатность и возможность запуска Codex проверять отдельно.

## Автозапуск и границы денег
- Сейчас `.github/workflows/codex-cave-opt-in.yml` существует, но **Codex в нём не запускается**, пока `CODEX_AUTORUN_ENABLED=true` не установлен и `OPENAI_API_KEY` не предоставлен. Отдельный OpenAI API может стоить денег сверх подписки ChatGPT, поэтому без разрешения владельца не включать.
- Никаких новых платных инструментов. GitHub Pages — единственный релизный контур; Vercel в бете не нужен.
- **Никогда** автоматически не сливать draft PR, не изменять production Supabase/Edge/авторизацию/кошелёк, не стирать данные игроков. TERRITORY 2.0 не трогать.
