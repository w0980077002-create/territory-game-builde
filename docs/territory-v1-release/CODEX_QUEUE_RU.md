### Контроль исполнения, а не активности

Для каждой задачи фиксировать **issue → исполнитель/канал запуска → ветка/PR → проверенный diff → CI → merge SHA → Pages SHA → видимый мобильный эффект**. Отсутствие нового кода и мерджа нельзя обозначать «в работе» только потому, что heartbeat или QA прошёл. Обнаруженные слабые черновики отклонять с конкретной причиной; acceptance-критерии небольших CSS-задач писать как `QUALITY_MIN_GRADIENT_LAYERS:`, `QUALITY_REQUIRE_TRANSPARENT_EDGE: yes`, `QUALITY_REQUIRED_VALUE_TEXT:` при необходимости; эти условия проверяются бесплатным агентом до сохранения его кода.

**Система контроля:** периодическая автоматизация ChatGPT отвечает за попытку реально брать безопасную задачу и проверять публикацию; ежечасный GitHub `LEAD` остаётся лишь read-only диагностикой и не заменяет разработку. Нельзя обещать, что сторонний Codex непрерывно работает, пока нет подтверждения его запуска.

## Шаблон завершения любой задачи

- **Проверено:** команды/результаты, мобильная ширина, реальный Telegram или «не проверено».
