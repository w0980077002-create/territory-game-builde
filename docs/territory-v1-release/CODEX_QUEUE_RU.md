**Конкретное ТЗ:** (1) обновить ветку от актуального `main` с уже слитыми исправлениями обычного Похода/Арены; (2) исправить блокеры доверенной экипировки, навыков и рун на основании существующих подтверждений, а не произвольного `game_state`/`player_inventory`; проверить игрока с legacy экипировкой, пустым UUID-списком и изменением fighter snapshot; (3) сохранить происхождение партий пояса, провести расход и боевой эффект эликсира, списание и квитанцию атомарно на сервере, либо честно отключить эффект/пояс в серверном режиме до доверенного механизма; (4) проверить старт/шаг/финал боя, 100 этажей, тёмные камни (5 на старт, +3 в 00:00 UTC, 1 за вход), победу/поражение и no-double-credit; (5) сеть/повтор/двойной тап/восстановление не блокируют обычный Поход/Испытания; (6) устранить реальные причины красных `adventure-postgres` и mobile тестов, не выключать проверки.

**Проверки:** `npm run typecheck`, `npm run build`, `npm run test:adventure-server`, `npm run test:pve`, целевые экономические/боевые тесты, **настоящий PostgreSQL 17 с параллельными транзакциями**, мобильный browser fixture, реальные Telegram-сценарии по мере доступности. Не объявлять продакшен-реализованным, если тест только симулировал сервер.

**Выполнено, когда:** три режима независимы; серверная награда и списание однократны; данные 100 существующих игроков не ухудшены; PR безопасен к слиянию, CI зелёный; Pages опубликован на нужном SHA; честно описано, что из Telegram проверено. **Блокировка:** на 30.10.2026 доверенный источник legacy владения/происхождения пояса и атомарный расход полностью не решены. Никаких клиентских подмен и wipe.

## Шаблон завершения любой задачи
- **Версия:** PR, merge SHA, опубликованный Pages SHA/URL (либо чётко «не опубликовано»).
- **Игрок видит:** путь нажатий и что изменилось.
- **Проверено:** команды/результаты, мобильная ширина, реальный Telegram или «не проверено».
- **Сохранения:** какие данные могли затронуться, до/после без персональных данных.
- **Осталось:** только конкретный блокер и **следующая задача** из очереди. Не создавать новую архитектурную программу.

Ни GitHub issue, ни `AGENTS.md`, ни этот файл не запускают Codex сами по себе. Исполнитель должен получить задачу через действующий механизм запуска Codex, читать эту очередь и подхватывать первый незавершённый пункт.
