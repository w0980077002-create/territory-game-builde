# TERRITORY 1.0 — визуальная книга навыков, контракт для Codex

**Состояние:** визуальный прототип T1/T2 в отдельной ветке `chatgpt/rune-skill-ui-20261028`; не публиковать до связи с серверной механикой T3. **Не менять боевой алгоритм, валюты, сохранения или базу данных в этом пакете.**

## Где находится работа

- `src/game/config/territory-rune-skill-book-v1.json` — пять групп **База/Ядро/Контроль/Пробуждение/Финал**, в каждой три навыка; у каждого по три рунических варианта; шесть пассивных кандидатов (три слота). Доступные названия и эффекты — **оригинальные предварительные тексты TERRITORY** для дизайна, не игровые цифры и не свидетельство реально включённых способностей.
- `src/components/builds/RuneSkillBook.tsx` — адаптивное меню, окно навыка и выбор внутренней руны. События выбора выдаются через `onSelectionChange`, если внешняя модель передаст callback. Сейчас внешний callback не передан: **сохранения и действующих боёв нет**.
- `src/components/builds/runeSkillBook.css` — отдельный класс `rune-book`, тёплое дерево и яркие шестигранники, без трогания старых CSS.
- `src/components/ProfileScreen.tsx` — пункт книги на экране героя, отдельный от прежнего `BuildTrainingPanel`. Переход `Карта → Руны` открывает новую книгу; тренировочная лаборатория остаётся прежней.
- `scripts/check-rune-skill-book.mjs` — статические проверки схемы, пяти рядов/15 навыков/45 рун, границ визуального режима.

## Выходной интерфейс

```ts
type RuneSkillBookSelection = {
  skillIds: Record<string, string>;  // groupId -> skillId, один из трёх
  runeIds: Record<string, string>;   // skillId -> runeId, один из трёх у навыка
  passiveIds: string[];             // <= 3
};
```

`RuneSkillBook({ language, initialSelection?, onSelectionChange? })` **не пишет в GameState** и не подтверждает экипировку сервером. Никаких реальных уровней, шансов срабатывания или чисел бонусов в каталоге пока нет. В карточке они прямо названы ожидающими подключения.

## Зависимость Codex T3

1. Уточнить игровой каталог навыков и идентификаторы/эффекты для всех пяти рядов: текущие описания являются макетом механики; совместить их с проверенной системой рун, не подменять фиктивной формулой.
2. Создать серверно проверяемые права на навыки/руны, уровни, сохранение выбора и результаты боя; отдать в UI значение `initialSelection` и обработчик `onSelectionChange`. Клиентское изменение нельзя считать экипировкой до серверного подтверждения.
3. Сохранить ручную/автоматическую арену, PvE и существующее обучение; не затрагивать скрытый вход админа, прогресс и любые реальные покупки.
4. После интеграции убрать надпись о предпросмотре **только** когда боевой эффект и сохранение действительно проверены и тесты проходят.
