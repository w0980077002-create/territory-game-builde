## Граница Supabase после решения владельца 16.11.2026

- PvE (движение, противники, кадры и эффекты) работает в браузере без серверного combat tick. Пещера использует облачные status/start/finish и защищённый учёт прогресса/камней. Не создавать второй backend для неё.
- Боевой экран лениво загружает CaveExpeditionPreview только при входе в Пещеру; старый ServerAdventureScreen подгружается только для восстановления старой квитанции. PvP, награды, сохранения и платежи остаются серверными.
- Резервные таблицы и SQL-миграции, необходимые для recovery Stage8 и сохранений игроков, не удалять вслепую. Статус эксплуатационных cron и live-объектов сверять в самой Supabase.

## Быстрый локальный запуск

Нужны Node.js 20, npm и существующий lockfile. Не затирать настроенный `.env` или `.env.local`. `VITE_*` видны клиенту; service-role/секреты туда никогда не помещать. Локальная игра с реальными `VITE_SUPABASE_*` **может работать с настоящим сервером** — для безопасных тестов выбирать изолированный проект или штатные фикстуры.

```sh
npm ci
cp .env.example .env  # только если файла ещё нет; указать тестовый Supabase
npm run dev
```

Обычная игра открывается по базовому пути `/territory-game-builde/`. Для автономной диагностики Пещеры без учётной записи можно собрать `npm run build:cave-preview`; это **технический артефакт для разработчика**, не дополнительная игра, не новый путь обязательной приёмки владельца.

## Как работать быстро и безопасно

1. Установить **одно актуальное поручение**. Обязательно сверить свежий `main`, используемые компоненты, старые PR и возможные конфликты. Исторические `docs/territory-v1-release/CODEX_QUEUE_RU.md`, `WORKING_AGREEMENT_RU.md`, старое DEMO-описание и handoff — **архив**, не источник новых ролей, серверных боёв, запретов публикации и задач.
2. Не плодить параллельные приложения и PR: Codex интегрирует одну TERRITORY; Claude может выполнять независимый согласованный блок. Небольшую задачу не дробить. Не переписывать рабочую механику ради визуального улучшения. Три транспортных ZIP больше не нужны в рабочем дереве: исходный набор распакован в VIKING `territory-game-working/assets/characters/v2-source/` (EXTRACTION_REPORT.json, тот же SHA256 исходного архива). Оригинальные три ZIP доступны в историческом коммите TERRITORY `06234080f7e3da6456f4398fe4f70774b1c6dec0`. Для ручной проверки скачанных частей: `python scripts/check-character-art-pack.py --archive-dir /path/to/downloaded/parts`. Не распаковывать снова без необходимости.
3. Для исправлений/визуала — `npm run typecheck`, `npm run lint`, `npm run build`, адресные проверки из `package.json`, реальный браузерный сценарий RU/EN 320/360/390/430, где уместно. Не объявлять Chromium физическим Telegram WebView. Проверять сохранение, поражение, выход, повторные запросы и восстановление, если задача касается этих путей.
4. Для Пещеры во время разработки — релевантные проверки из `test:cave-expedition`, `test:cave-expedition:browser`, `test:cave-animation:browser`, `test:cave-playtest`; полный необходимый CI на итоговом SHA выполняется штатно; при изменении данных дополнительно соответствующие PGlite/PostgreSQL и receipt-тесты. Playwright/Python/Chromium предусмотрены в `.github/workflows/cave-expedition-preview.yml`.
5. Уже утверждённую безопасную работу, прошедшую проверки, публиковать самостоятельно через PR → `main` → единственный GitHub Pages. Проверить SHA релиза и послерелизный verify. Реальная приёмка владельца — **открыть привычную TERRITORY в Telegram**, а не качать артефакты. Нужны отдельные разрешения только на опасные SQL/сбросы/реальную экономику, как записано в `AGENTS.md`.

## Утверждённые границы архитектуры и хостинга

## Утверждённая граница Supabase · 16.11.2026

Владелец утвердил: **Supabase только для необходимой авторизации, серверных сохранений/прогресса, кошельков (золото, алмазы, VIP), инвентаря/экипировки/кузницы/профессий, PvP Арены и рейтингов, аукциона/торговли/платежей, проверенных наград и квитанций**. В Пещере через сервер идут только необходимые status/start/finish, камни, глубина, история и защищённые подтверждения. **Обычный PvE-бой, движение, удары, анимации, VFX и камера исполняются локально на телефоне.** Не добавлять серверный combat tick, дополнительные SQL/Edge/таблицы для косметики и кадров. Устаревшие тестовые системы и резервные таблицы удалять только после проверки отсутствия активных обращений, recovery-потребителей и наличия нужных бэкапов; исторические миграции не удалять. Не отключать RLS, CAS, защиту экономических операций и действующие cron-режимы.
