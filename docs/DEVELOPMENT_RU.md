# TERRITORY — разработка и продолжение Пещеры

Правила исполнителя: [AGENTS.md](../AGENTS.md). Этот документ описывает код, а не создаёт новые игровые правила. Сохранённые игровые требования — [GAME_REQUIREMENTS_RU.md](GAME_REQUIREMENTS_RU.md). Состояние сверено 14.11.2026; результаты проверки: [REPOSITORY_AUDIT_20261114_RU.md](REPOSITORY_AUDIT_20261114_RU.md).

## Запуск

Нужны Node.js 20 и npm. Использовать существующий `package-lock.json`:

```sh
npm ci
cp .env.example .env
# Заполнить VITE_SUPABASE_URL и VITE_SUPABASE_ANON_KEY своего тестового проекта.
npm run dev
```

Не перезаписывать уже настроенный env-файл вслепую. Vite также читает `.env.local` и `.env.development.local`; их значения могут перекрывать `.env`. Проверить выбранный тестовый проект перед запуском.

Открыть адрес Vite с путём `/territory-game-builde/`. Переменные `VITE_*` видны браузеру: здесь допустим только публичный anon/publishable key, никогда service-role/secret. Обычный локальный запуск использует указанный Supabase и не является автоматически изолированной песочницей. Для теста Пещеры без аккаунта и базы:

```sh
npm run build:cave-preview
# Открыть artifacts/cave-expedition/territory-cave-demo.html в браузере.
```

Это автономная сборка того же компонента, все изображения встроены, сеть запрещена CSP. Её не надо подключать как вторую игру или отдельный deploy. Игровой маршрут: **Поход → Тёмная пещера → Новая экспедиция · тест → Играть DEMO**.

## Карта кода

| Область | Где искать | Ответственность |
| --- | --- | --- |

| Сохранения | `src/game/cloud.ts`, `saveQueue.ts`, `immediateSave.ts`, `walletVersion.ts` | Серверная синхронизация; не обходить квитанции и блокировки |
| PvE | `src/components/BattleScreen.tsx`, `src/components/pve/`, `src/game/pve.ts` | Поход, Испытания, маршрутизация Пещеры |
| Реальные этажи Пещеры | `src/components/pve/ServerAdventureScreen.tsx`, `src/game/combatV1/`, `src/game/cave/` | Серверный прогресс, попытки, восстановление, существующие системы |

| Движок DEMO | `src/game/cavePreviewWorld/engine.ts` | Локальный автомат состояний, бой, умения, маршрут; `BALANCE` и `SKILLS` только для DEMO |
| Контент DEMO | `src/game/cavePreviewWorld/catalog.ts` | Биомы, противники, развилки |
| Показ DEMO | `src/components/pve/cavePreview/` | Canvas-рендерер, звук, CSS |
| Изображения | `public/assets/territory/` | Одобренные ассеты; не подменять их макетом экрана |
| Backend | `supabase/functions/`, `supabase/migrations/`, `supabase/staged/` | Код и история SQL, не доказательство фактической активации на сервере |
| Проверки | `scripts/`, `package.json`, `.github/workflows/` | Локальные регрессии, CI, единственный Pages deploy |

Не объединять DEMO и реальные этажи механическим переносом кода. У них разные гарантии: локальная демонстрация теряется при обновлении, а настоящий бой должен восстанавливаться и выдавать награду ровно один раз.

## Проверки по задаче

База: `npm run typecheck`, `npm run lint`, `npm run build`. Для игровых изменений добавить адресную проверку и браузерный сценарий. В репозитории много исторических проверок исходного текста: они полезны как ограничения, но не доказывают настоящий бой или активацию SQL.

Для Пещеры:

```sh
npm run test:cave-expedition
npm run test:cave-expedition:browser
node scripts/check-cave-systems.mjs
node scripts/check-cave-belt-attestation.mjs
node scripts/check-dark-stones.mjs
node scripts/check-adventure-client-ui.mjs
node scripts/check-adventure-receipt-adapter.mjs
node scripts/build-journey-preview.mjs
python scripts/check-journey-browser.py
```

Браузерные проверки требуют Python с Playwright и Chromium. Зависимости и версии описаны в существующем `.github/workflows/cave-expedition-preview.yml`; `CAVE_BROWSER` позволяет указать исполняемый файл браузера. Проверки используют локальный HTTP-сервер и изолированные фикстуры. Доступ к production для них не нужен.

Отчёт/кадры экспедиции: `artifacts/cave-expedition/evidence/` (не коммитить сгенерированный HTML). Проверка интеграции использует настоящий `BattleScreen` с поддельным транспортом, не аккаунты игроков. Перед публикацией дополнительно сохранять серверные гарантии затронутого PvE-пути.

## Что уже есть и что делать дальше

**Есть в коде DEMO:** три комнаты, две независимые пары порталов, четыре маршрута, ручные/автоматические умения, босс с тремя фазами, победа/поражение/повтор, RU/EN, звук и изоляция от данных игрока. Не начинать это повторно по старому ТЗ. Подробности: [CAVE_EXPEDITION_DEMO_RU.md](CAVE_EXPEDITION_DEMO_RU.md).

**Новые персонажи P0:** [исполнительное ТЗ](CODEX_CAVE_CHARACTERS_VERTICAL_SLICE_20261111_RU.md) конкретизирует сцену на существующем коде. Пакет уже есть: три корневых `TERRITORY_art_v2_Codex_*_of_3.zip` содержат части одного ZIP. Его SHA256 подтверждён: `d8bd7c242accd3396232a53cae7fe47478c4b6aae558b95dbad0c68edf5c1fa1`. Внутри 21 мастер PNG, 21 still WebP, манифест и исходные референсы. Проверить и распаковать в **новую** локальную папку:

```sh
python3 scripts/check-character-art-pack.py
python3 scripts/check-character-art-pack.py --extract-to /tmp/territory-art-v2-review
# При установленном Pillow — проверка RGBA и прозрачности:
python3 /tmp/territory-art-v2-review/TERRITORY_ART_PACK_2026-11-11_v2/validate_art_pack.py /tmp/territory-art-v2-review/TERRITORY_ART_PACK_2026-11-11_v2
```

Ссылка из транспортного README на `scripts/import-approved-characters-v2.mjs` устарела: такого импортера в текущем дереве нет. Команда выше даёт воспроизводимый доступ к исходникам без него. Архивные инструкции о ветке PR #491 не возобновлять. Изображения пока не подключены в игру и не являются готовой анимацией. Следующая задача может использовать эти исходники без повторного запроса файлов; сохранять действующий арт, проверять пригодность выбранных персонажей и анимацию по событиям боя.

**Следующий шаг:** продолжать текущую задачу владельца. Для Пещеры — первая проверенная сцена с выбранными персонажами на существующем движке и исправление конкретных замечаний по управлению, сцене и ритму. Личная проверка владельцем на телефоне нужна для оценки результата, но не блокирует подготовку и локальную проверку реализации. Chromium и зелёный CI не заменяют эту оценку.

**После принятия игрового цикла:** описать и проверить серверный multi-room run — один входной камень за забег, авторитетные волны/выборы, resume, идемпотентное завершение, один набор наград, отсутствие повторного списания при обрыве связи. Сначала локальные/изолированные тесты, затем конкретно согласованная активация. Не отдавать настоящие награды по локальному DEMO-результату.

**Далее P1:** тёмная экипировка, гемы, пещерное Благословение, склад и инструменты администратора на существующих контрактах. Цены эликсиров, шансы, максимальный уровень гемов и другие неутверждённые правила требуют решения владельца. Не угадывать их по картинкам.

Исторические handoff и очередь сохранены как контекст. Их назначения и старые требования повторного разрешения на каждый безопасный merge не являются действующими правилами.

## Автоматизация

Работу ведёт текущий исполнитель до проверенного результата. Для сложной задачи можно использовать дополнительного агента с независимым объёмом; заводить профили и отдельную систему диспетчеризации не требуется. Экспериментальный Qwen-dispatch, «команда специалистов», почасовой triage и 15-минутный монитор удалены. Они не требуются игре и не завершают игровые задачи.

Сохранены `review-ci.yml` (регрессии PR), `pages.yml` (единственная публикация), `verify-published-pages.yml` (проверка после выпуска) и специализированные проверки механик/браузера. Список команд остаётся в `package.json`; расписание для повторных служебных отчётов не нужно. Старые закрытые/черновые задания не возобновляются по одним меткам `[AI:*]` или `[AGENT:*]`.
