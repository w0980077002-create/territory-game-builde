# Гусь-Обнимусь — issue #479

Одна запись каталога `follower_goose_obnimus`, существующий активный PvE-спутник, обычные Поход и Испытания (`PveFight`/`playRound`). Ни нового боевого слота, ни маршрута демонстрации в игре. PvP и серверная Пещера не получают новых бонусов. Подпись «Адвокат 5000 побед» косметическая; уровень гуся 1, автоматической выдачи уровня 100 нет.

## Перенос и баланс

Источник: `w0980077002-create/territory-game-working` @ `645eab542a9f9ec42a26917dcb4ea9edc39b8175`.

Без изменения пикселей перенесены `goose_aviator.webp`, `run-goose_aviator.webp` и атлас `animation-allies.webp`. В `frames.json` — только исходные прямоугольники и опорные точки гуся из `run-frames.json` / `animation-frames.json`. Другие персонажи атласа не отображаются. Исходные `CompanionBrain.ts` и `companions.ts` изучены: перенесены характер, реакция на босса и причинная модель пике; чужие таймеры, эволюции, награды и боевая система не копируются.

- Прямая атака 11 (7 × легендарные 1.6, округление), без произвольной прокачки сохранёнными полями.
- Пике: раз в четыре раунда против дальнего противника; против существующих магических боссов — один раз за бой после их первого удара. Отменяет реальный ответ врага, не наносит отдельного сверхурона.
- Обнимусь: каждый третий раунд, 20% от входящего удара, максимум 12 HP.
- Переполох: обычный удар спутника + отвлечение (5%, максимум 4 HP), только при реальном попадании спутника.
- ГА-ГА: после каждого четвёртого цикла со смещением на второй раунд — +5% к следующим ударам героя и спутника. Действующие ограничения суммарного урона босса сохраняются.
- Анимации не изменяют HP. Получение урона — реакция спутника на удар по герою; отдельного здоровья/полоски у гуся нет.

## Владение и безопасность

Один серверный ledger с уникальным `player_id` и квитанцией. Покупка и подарок берут одну блокировку строки игрока. Повтор с другого устройства/другим operation UUID возвращает существующее владение без повторной оплаты.

Покупка использует **существующий** `territory_private.territory_master_license_red_wallet_v1`, CAS ревизию и действующую защиту autosave. Стоимость 30 красных; клиент не списывает валюту. Нового кошелька, seed/переоценки балансов нет. Неопределённый сетевой результат оставляет старые записи заблокированными до перезахода/синхронизации. После входа владение читается серверным RPC; сохранённый клиентский флаг/список спутников не является основанием для открытия.

Подарок: существующая админка → поиск `@Amiksor` → карточка с полными player_id и Telegram ID → подтверждение пары → `goose_gift`. Edge проверяет обычный административный токен, SQL повторяет сверку ID/username под блокировкой. Персональный action ограничен Amiksor. Владение, одно письмо с точным текстом постановления и одна запись аудита создаются одной транзакцией. Полезная нагрузка письма `{}` совместима с действующим строгим claim; награда уже находится в ledger и повторно не начисляется кнопкой письма. После серверной проверки доступна кнопка «Посмотреть спутника».

Read-only сверка production подтвердила единственную пару ID для username Amiksor, уровень 61 и 5000 побед. Идентификаторы отображаются в защищённой админке; в публичный репозиторий персональные ID не помещены. Перед реальным действием проверить их повторно. Реальная выдача **не выполнена**.

## Проверка

`npm run test:goose` — изолированные PGlite транзакции, боевые правила и клиентский протокол квитанций/защиты сохранений. Проверяет оба порядка покупки/подарка, повторы, неверный Telegram ID, недостаток валюты, привилегии, одно письмо, сохранность старых спутников и остальных ресурсов. Это не нагрузочный тест двух параллельных PostgreSQL соединений.

`npm run test:goose:browser` — QA harness настоящих `FollowersPanel` и `PveFight`, без production транспорта или ключей. В игре нет ссылки на этот harness. Проверяет 320/360/390/430 RU/EN; снимки и запись находятся в `/tmp/territory-goose-evidence`. Reload здесь проверяет загрузку из изолированного ответа сервера, не реальный аккаунт production.

**Физический Android Telegram WebView не проверен:** подключённого устройства/ADB нет. Не считать Chromium доказательством этой проверки. До выпуска на телефоне проверить общий путь: Рюкзак → Спутники → выбор → Поход/Испытания → пике против Тёмного жреца → победа/поражение → перезапуск. Проверить неподвижность фиксированных панелей, читаемость карточки и отсутствие обрезания во время атаки. До разрешения production не проводить платную покупку на живом аккаунте; использовать изолированную базу/тестовый аккаунт.

## Конкретные серверные шаги — только после разрешения

1. После визуальной приёмки владельца применить **только** `supabase/staged/territory_goose_companion_v1.sql` в рабочем проекте, указанном конфигурацией игры. Проверить определения существующих таблиц и доступность доверенного кошелька; не применять заново SQL его инициализации.
2. Обновить **существующую** Edge Function `admin-api` кодом этого PR, сохранив её настройки и секреты. Ни новой Edge Function, ни новых секретов не требуется.
3. После разрешённого выпуска клиента через единственный workflow GitHub Pages проверить опубликованный SHA штатным `scripts/check-published-pages.mjs`. Vercel не используется.
4. **Отдельное разрешение на выдачу:** администратору снова сверить точные player_id/Telegram ID @Amiksor и нажать подарок. Проверить серверную квитанцию, единственную строку ledger и письмо. Без этого шага не объявлять, что подарок получен.

Остановка при проблемах: отозвать EXECUTE на buy/gift RPC, сохранив status, ledger, письма и аудит. Не удалять владение, не пересчитывать кошельки, не откатывать чужие сохранения. В этом PR production SQL/Edge/рассылки/покупки не запускались; merge и публикация до визуальной приёмки не выполняются по AGENTS.md.
