# Серверная основа приключений — staging

Это не выпуск и не миграция production. Установка новых файлов сама не включает бой и не меняет игроков; каталог врагов, правила и награды не заполнены. Старый PvE и Арена не переключены.

Для изолированной базы порядок установки: `territory_v1_combat_completion.sql`, `territory_v1_adventure_settlement.sql`, `territory_v1_combat_profiles_reconciliation.sql`. Edge `territory-combat` предназначен только для проверенного тестового окружения. Флаги `enabled` и `settlement_ready` по умолчанию выключены. Не включать их в production.

Серверный движок фиксирует результат в сессии и в той же транзакции записывает квитанцию, изменяет существующие поля `players` и открывает следующий этап. Ключ квитанции — ID сессии; повтор завершённого этапа сейчас запрещён до утверждения правил повторных наград. Награды и встречи должны быть явно настроены и разрешены. Предметы пока запрещены: существующий подтверждённый контракт выдачи ещё не подключён.

Подготовка профиля через Edge `{"action":"prepare"}` использует только закрытую аттестацию проверенной проекции; при отсутствии или расхождении сохраняет заявку на сверку и не меняет игрока. Аттестации нельзя создавать клиенту или service_role. Сравнение полного снимка намеренно консервативно: после любого изменения сохранения, включая награду, потребуется новая подтверждённая проекция. Автоматического достоверного источника исторических предметов и характеристик пока нет. Пересоздание профиля сохраняет выбранную сборку, а движок повторно проверяет владение перед боем.

При восстановлении завершённой сессии возвращается сохранённая квитанция с историческими `game_state` и `updated_at`. Клиентская интеграция должна применять её через существующую защиту ревизий и очереди сохранений; нельзя поверх более новой версии записывать старый снимок. Экран и эта интеграция в текущую задачу не включены.

`npm run test:adventure-server` использует изолированный PGlite с тестовыми данными и запускает настоящий движок и SQL. Это не проверка двух независимых соединений PostgreSQL, полной production-схемы с её триггерами, Telegram или переноса существующих игроков. Проверка этих сценариев, подтверждённые награды и характеристики, безопасное принятие квитанции клиентом и контракт предметов остаются обязательными до cutover. Создание ветки Supabase было отклонено: сервис сообщает, что Branching доступен с тарифа Pro.
