# Монополия TERRITORY v2

Изменения подключены только для `game === 'monopoly'` в `HallPlayScreen`. Другие игры, App, админка, авторизация и скрытый вход не изменены. Старый, отключённый `MonopolyScreen` не используется.

Реализованы ромбовидное поле из 28 клеток, пошаговое движение героя, анимация кубика, режим без анимации и учёт reduced motion; режим наград ×10 за 10 билетов; просмотр и получение наград за 5/10/15/20/25 кругов; ежедневный подарок; три задания с настоящим прогрессом; три бесплатных предложения с условиями; события «сокровище», «телепорт», «удвоенный следующий ход» и «выбор следующего кубика»; показ полученной награды и сохранение незавершённого хода. Таймер события хранится на сервере и длится 72 часа. По окончании сбрасываются только показатели и награды события, кошелёк сохраняется.

Новый пейзаж выполнен оригинальным SVG и CSS. Герой, корабль и монеты взяты из существующих ресурсов TERRITORY. Фотографии используются как референсы компоновки и механики, их графика не переносилась.

Баланс использует существующие серверные билеты и золото зала. Клетки выдают золото, задания/круги/предложения — билеты. Полученное золото забирается существующей кнопкой в игровом зале. Алмазы, материалы, реальные платежи и рекламные просмотры не симулируются: действующий зал не имеет соответствующего API. Предыдущее ТЗ не найдено в доступном контексте; точные цены, награды и внешние задания из него требуют отдельной сверки.

## Серверная установка

Серверный SQL: `supabase/staged/territory_monopoly_v2.sql`, после существующей миграции `20261017_game_hall_five_v1.sql`. Две приватные таблицы с RLS (прогресс и список приглашённых тестировщиков) и один RPC. Существующие RPC других игр не заменяются. Списание, события, бонусы, круги и выдача проверяются сервером под блокировкой кошелька; поддерживается существующий кошелёк до 1000 билетов (включая выдачу админкой) и лимит 1000 золота в сутки, повторное завершение хода не дублирует награду. Общий дневной подарок +2 совпадает с подарком игрового зала.

SQL проверен локально в PGlite. В рабочую БД он не применён: `supabase/staged/README_RU.md` требует резервную копию, отдельную проверку и подтверждение владельца перед применением staged SQL. До установки экран покажет понятное сообщение об отсутствующем серверном обновлении. После установки доступ открыт только аккаунтам из серверного списка приглашённых. Сначала установить SQL в тестовой БД, затем проверить авторизованным пользователем; публиковать клиент после серверного обновления.

## Проверки

- `npm run typecheck`
- `npm run build`
- `npm run test:hall`
- `node scripts/check-monopoly-v2.mjs`

Новый SQL-тест проверяет авторизацию, приватность таблицы, изоляцию игроков, билеты ×1/×10, восстановление хода, защиту от повторной выдачи, выбор кубика, удвоение перемещения, круги, бонусы событий, задания, подарки, предложения, круговые награды, лимит золота, смену события и сохранение другой активной игры.

Визуальная проверка браузером в текущем окружении заблокирована sandbox: Chromium завершается с `setsockopt: Operation not permitted`, локальный Vite не может слушать порт (`EPERM`). Автоматическая браузерная проверка не подтверждена. Перед публикацией проверить 320/390/768 px, окна и анимацию, восстановление после перезагрузки, ошибки сети, английский язык и reduced motion.

Подготовка закрытого теста и результаты совместимости: [инструкция владельцу](../../../docs/monopoly/OWNER_TEST_GUIDE_RU.md), [технический порядок установки](../../../docs/monopoly/INSTALL_AND_REVIEW_RU.md).
