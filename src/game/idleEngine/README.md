# Изолированный idle-движок TERRITORY 1.0

Модуль не подключён к живой игре. Каталог передаётся вызывающим кодом: никаких импортов `idleContent`, React, Арены, сетевых клиентов, сохранений или начислений наград.

```ts
import {
  createIdleCombat, advanceIdleCombat, validateIdleLoadout,
  type IdleCatalog, type IdleLoadout, type IdleCombatEvent,
} from './src/game/idleEngine';

// Пример данных для API, не игровой каталог и не утверждённый баланс.
const catalog: IdleCatalog = {
  skills: [{ id: 'example', category: 'base', cooldownMs: 1000,
    energyCost: 5, priority: 1, multiplier: 1.2 }],
  runes: [], passives: [],
};
const loadout: IdleLoadout = {
  active: [{ skillId: 'example', runeIds: [] }], passiveIds: [],
};
const errors = validateIdleLoadout(loadout, catalog);
if (errors.length) throw new Error(errors.join('; '));
let combat = createIdleCombat({
  seed: 42, stage: 1, catalog, loadout,
  hero: { maxHp: 100, attack: 10, maxEnergy: 20, energyRegenPerSecond: 2 },
  enemy: { maxHp: 80, attack: 6 },
});

// Вызвать из существующего игрового таймера. Сам движок таймеров не создаёт.
const frame = advanceIdleCombat(combat, 1000);
combat = frame.state;
function render(events: IdleCombatEvent[]) {
  for (const event of events) {

    if (event.type === 'impact' || event.type === 'heal') {
      // Установить HP цели в event.hpAfter; урон/лечение уже применены движком.
    }
    // Остальные события управляют анимацией, позами и VFX, не повторным уроном.
  }
}
render(frame.events);
```

## Данные и выбор способностей

- Все шансы, пороги доли HP и силы `slow/mitigation/crit/precision` задаются долями 0…1. Все времена — миллисекунды. `multiplier` умножает физическую атаку; при его отсутствии навык применяет только эффекты. Без готового навыка используется базовый удар с множителем 1.
- До трёх кандидатов в категории `base/core/control/awakening/final`; до одного выбранного в каждой категории, до пяти активных навыков и трёх различных пассивок. Пустая сборка допустима. Пассивки один раз прибавляют `modifiers` к базовым статам героя, затем статы нормализуются.
- Навык выбирается из экипированных: доступная энергия, завершённый КД, выполненные условия. `selfHpBelow/enemyHpBelow` включают равенство; `energyAtLeast` — абсолютное количество энергии. Больше `priority` — раньше применение, одинаковый приоритет разрешается лексикографически по ID. Энергия и КД расходуются на `attack_start`, даже если последующий удар будет уклонён.
- Для настоящей серии ударов навык может задать `hitCount: 2 | 3` и `hitGapMs` (20–3000 мс). Каждое попадание — самостоятельный контакт с отдельным `contactId`, `hitIndex`, `hitCount`, отдельной проверкой уклонения/блока/крита и ровно одним списанием HP. Общий физический множитель делится между ударами поровну, энергия и КД списываются **один раз** на всю серию. Эффекты самого навыка накладываются после последнего успешного контакта, привязанные руны могут сработать на каждом контакте с соблюдением КД. Смерть отменяет оставшиеся удары серии. Для обычных навыков `hitCount = 1`.
- До двух разных рун на выбранном навыке. Нужен непустой список совместимых `skillIds` или `categories`; при наличии обоих действуют оба ограничения. Одну руну можно прикреплять к нескольким совместимым навыкам, её КД ведётся отдельно для каждой пары навык/руна. Неэкипированные руны не работают.
- Руна проверяется только на контакте исходного навыка после его эффектов. Уклонённая атакующая способность не вызывает эффектов или рун. Способности с нулевым физическим множителем применяют эффекты без проверки физического уклонения. КД руны начинается только при реальном применении хотя бы одного эффекта; нулевой шанс, нулевая сила, полная энергия и полностью поглощённый магический эффект не дают фиктивный `rune_proc`. Событие прока предшествует его эффектам, включая смертельные. Ни эффект, ни периодический тик не запускают новые проки.

## Эффекты и урон

- `burn`: `strength` единиц периодического урона, `durationMs`, `tickMs`. Тик на границе окончания включён; физическая защита не вычитается, mitigation действует. Каждый тик — самостоятельный `impact` с `source: 'burn'` и `statusId`.
- `slow`: доля замедления следующего интервала атаки. Интервал делится на `1 - strength`; полное замедление запрещает начало новой атаки до истечения статуса. Уже запущенный удар не прерывается.
- `mitigation`: доля поглощения физического, магического и периодического урона.
- `crit`: добавка к шансу критического удара. `criticalMultiplier` берётся из статов, не из фиксированных коэффициентов движка.
- `precision`: добавка к точности. Вероятности уклонения и блока противника умножаются на `1 - precision` атакующего.
- `magic`: мгновенный урон `strength`, игнорирующий физическую защиту; mitigation действует.
- `energy`: мгновенное восстановление `strength` энергии, ограниченное `maxEnergy`; фиксируется через `status_apply` с `source: 'energy'`, длительного статуса не создаёт.
- `heal`: мгновенное восстановление `strength` здоровья (не выше `maxHp`). Единственное событие `heal` содержит `value` и окончательное `hpAfter`. Полное здоровье не даёт фиктивного лечения или прока руны. Урон по-прежнему списывается только через `impact`.
- По умолчанию `burn/slow/magic` направлены на противника, остальные эффекты — на себя. Явное `target: 'self' | 'opponent'` меняет направление. Временные бонусы суммируются до 1. Эффекты навыка вступают в силу после его физического контакта, влияют на последующие расчёты. Повторный статус того же типа/источника заменяет старый с парой `status_expire/status_apply`; таймер ближайшего тика ожога сохраняется.
- Порядок физического расчёта: уклонение → критический множитель → вычитание защиты → снижение блоком → mitigation → ограничение оставшимся HP. Ровно один `impact` с `source: 'attack'` на контакт, включая нулевой урон. Дополнительный магический эффект имеет отдельный `impact` с `source: 'magic'`. `critical/block/dodge` — только аннотации, не повторное списание HP. `contactId` связывает запуск, контакт и его модификаторы; `statusId` связывает наложение, тики и окончание статуса.

## Боссы и спутники (пока только тестовая симуляция)

- `enemyAbility` и `nextEnemyAbilities` задают индивидуальную способность каждого врага, включая усиленные и элементальные атаки боссов. Враг применяет способность по КД, иначе совершает обычный удар. Это отдельный каталог поведения врагов, он не расходует руны героя и не меняет серверную Арену.
- `companions`: до пяти разных спутников с независимыми `intervalMs`, `windupMs`, силой удара и эффектами. `companion_start` заранее сообщает рендереру о настоящем действии. Физический удар спутника — отдельный `impact` с `source: 'companion'` и `companionId`; магия, лечение и защитные эффекты реализуются через тот же движок. Действия сдвинуты во времени, отменяются смертью и детерминированы.
- Рендерер не должен начислять никакую добычу за `stage_clear/loot_visual`. Данные предметов и реальные награды не являются частью этого движка.

## Время и жизненный цикл

Шаг фиксирован: 20 мс. Остаток времени хранится в `remainderMs`, положительные кадровые интервалы суммируются. Тайминги округляются вверх до шага, нулевые КД/таймеры ограничиваются одним шагом. Состояние и события воспроизводимы для одинакового seed и общего времени, включая разные разбиения кадров. Снимки независимы от входных объектов и предыдущих состояний, сериализуются в JSON и могут быть продолжены после восстановления.

`createIdleCombat` возвращает состояние с начальными событиями в `pendingEvents`. Первый положительный вызов `advanceIdleCombat` доставляет их один раз. Внутри шага сначала обрабатываются периодические эффекты/истечения, затем контакты (герой, противник), затем новые атаки. При одинаковом времени герой разрешает контакт первым; смерть отменяет оставшиеся удары. Завершённый бой не меняется и не генерирует новых событий.

По умолчанию подход занимает 300 мс, интервал атаки — 1000 мс, замах — 200 мс, переход этапа — 500 мс. Эти параметры задаются вводом/статами/навыками. `maxEnergy` и восстановление энергии по умолчанию нулевые; если `energy` не передана, энергия полная. Шансы и защита по умолчанию нулевые, критический множитель — 1.

Без `nextEnemies` победа завершает симуляцию. С конечной очередью `nextEnemies` запускается следующий противник с увеличением локального `stage`; HP героя, энергия и КД сохраняются. Все временные статусы завершаются при смерти/очистке этапа. `stage_clear/loot_visual` служат только для отображения, не содержат наград.

Защитный горизонт по умолчанию — 120 секунд, максимум — 600 секунд. Огромный конечный `elapsedMs` обрабатывается до горизонта или исхода боя: лишнее время после завершения не симулируется. Неразрешённый исход на горизонте — `timeout`. Отрицательные/нечисловые/бесконечные интервалы не меняют состояние. Повреждённый каталог/билд создаёт `phase: 'invalid'` и `validationErrors`; некорректные числовые статы нормализуются в конечные безопасные значения. Числовая граница статов и параметров каталога — 1e9, seed — uint32. Все циклы ограничены горизонтом и размерами каталогов/эффектов.

Проверки: `npm run typecheck`, `npm run test:idle-engine`.
