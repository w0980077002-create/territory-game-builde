# TERRITORY STAGE6 — большая интеграция экономики (на базе STAGE5)

**Дата:** 15.10.2026. **GitHub:** `w0980077002-create/territory-game-builde`, `main`, исходный коммит `4e8cb34072ec8d765e143b12e3d6d7ee167cbbfd` (полностью установленный STAGE5). Полный архив с графикой, кодом и текущими игровыми механиками, разбит на две последовательные бинарные части по <25 МБ. Не отдельный патч: текущий установщик использует `rsync --delete` для файлов проекта.

## Реально меняется на клиенте

1. **Безопаснее облачные сохранения.** STAGE5 защищал `updated_at`, но серверная покупка профессии может изменить `players.gems`, НЕ обновив время строки. Новый механизм сравнивает **одновременно** `updated_at`, `gold` и `gems`; старое окно игры не может незаметно отменить подтверждённое сервером списание. Если проверка не прошла, сохранение останавливается и просит игрока снова открыть игру. Для старого `game_state` миграции ничего не сбрасывают.
2. **Переход ремесла на настоящий сервер.** При наличии серверного RPC `territory_craft_status_v1` клиент проверяет флаг и реальные остатки ресурсов и уровень мастерства. Когда ремесло включено, передаёт только `recipeId` и UUID операции в существующий staged `territory_craft_v1`, сверяет чек и заново получает остатки с сервера. Повтор после потери сети использует тот же UUID, сохраняемый в сессии устройства. В аукционе торгуются лишь серверно-созданные экземпляры, а не предметы из произвольного `game_state`. При отсутствии нового RPC действует совместимый старый режим локального ремесла; он **не является защищённым**.
3. **Серверный магазин камней.** Подготовлен клиент к существующему staged RPC `territory_shop_buy_stones_v1`, который сам назначает цену и лимит **25 камней за день Europe/Kyiv**, требует проверенный серверный кошелёк и запоминает UUID операции. Добавлен статус серверного кошелька `territory_shop_status_v1`; по неоднозначному ответу покупка **не повторяется новым ID**. Пока серверный флаг магазина выключен, привычный магазин работает по-старому. Если флаг включится до готовности остальных категорий, клиент блокирует их покупки вместо выдумывания балансов.
4. **Проверки сценариев:** поддельные остатки/чеки, отрицательные ресурсы, повтор операций, сохранение UUID между перезапусками, защита от устаревшего сохранения, структура проекта, существующие PvP/сезоны/аукцион, основной release gate.

## Серверные файлы: подготовлены, но НЕ установлены в рабочую БД

- `supabase/staged/territory_stage6_craft_status.sql`: статус **проверенного** ремесла только своего игрока, с `auth.uid()`, проверкой профессии и banned, флаг выключен по умолчанию. Требует ранее подготовленный stage3 backend.
- `supabase/staged/territory_stage6_shop_status.sql`: статус только своего проверенного кошелька, серверная дата Киева, лимит магазина; не выдаёт деньги. Требует stage3 backend.
- `supabase/staged/territory_stage6_security_preflight.sql`: только чтение grants, RLS, состояния сохранений и критических RPC перед переходом.
- `supabase/staged/territory_stage6_production_cutover_GATE.sql.example`: намеренно запрещает запуск. НЕ отключайте прямую запись до замены **всех** клиентских расходов/начислений доверенными серверными действиями, проверки резерва и миграции существующих пользователей.

Никаких SQL-изменений, подключений оплаты, сбросов/обнуления прогресса, VIP, алмазов, золота, предметов или боевых этажей не выполнялось. Незавершённые серверные функции остаются **staged**, чтобы избежать ломания работающей игры и двойных списаний.

## Важная особенность GitHub-установщика

`unpack-project.yml` исключает `/.github/` из распаковки. Поэтому в архиве есть подготовленный безопасный вариант `.github/workflows/territory-pages-repair.yml`, но **он не обновит GitHub автоматически**. Текущий серверный коннектор не позволил заменить workflow (403 — недостаточно разрешений). Поэтому не заявляем, что обход `economy-release.json` в альтернативном Pages workflow ликвидирован: он всё ещё присутствует в **самом репозитории**. `pages.yml` имеет основной release gate (`ready=false`), но альтернативный workflow способен его обходить. Следующее устранение требует разрешённого способа изменения `.github` (не обычного ZIP). Нельзя выставлять `economy-release.json.ready=true`, пока API остаётся подделываемым.
