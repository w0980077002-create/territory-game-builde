# TERRITORY — Пакет №4: живые спутники, полный комплект кузницы, безопасные локальные действия

**Исходник:** main `b49470820d667264412acc020542a0292bde0bd3` (пакет №3). Полный проект: для существующего `unpack-project.yml` НЕ отправляйте отдельный мини-патч; `rsync --delete` удалит не включённые файлы.

## Реально работающие изменения игры

1. **Пять спутников и один активный на игрока**, выбор в разделе «Герой → Лагерь спутников»:
   - «Верный щит» — защита, от уровня героя 3.
   - «Северный воин» — дополнительный урон, с уровня 8.
   - «Лесная целительница» — восстановление HP между раундами, с уровня 15.
   - «Лунный охотник» — небольшой PvE-бонус шанса крита, с уровня 25.
   - «Рунный маг» — снижение защиты противника, с уровня 40.
   Нельзя назначить заблокированного спутника. При смене спутника один активный. Разные роли не складываются. Сила PvP не изменяется.
2. **Тренировка спутника** за золото и кузнечные материалы: серверные платежи НЕ используются. Стоимость растёт с уровнем; предел тренировки — уровень героя и абсолютный предел 60. Одно действие меняет один спутник, ресурсы списываются из актуального состояния. Бонусы умений ограничены, чтобы не создавать неограниченный урон.
3. **Безопасное продолжение старых сохранений:** «Верный щит» не удаляется; его уровень, атака, защита и старый ID остаются. Новые спутники добавляются по уровню героя. Локальные боевые камни, алмазы, профессии, экипировка, письма, VIP и пройденные этажи не сбрасываются. Новый выбранный спутник сохраняется в существующем `game_state`.
4. **Кузница — стимул улучшать все 7 слотов.** В интерфейсе теперь видно весь комплект. У каждого надетого предмета должен быть хотя бы один успешный апгрейд. За 3 разных улучшенных слота: +2% HP; за 5: +3% защиты; за 7: +4% атаки. Бонусы только в PvE, НЕ в серверной Арене. Учитывается только НОВОЕ или ранее корректно мигрированное значение `upgradeCount`, а не произвольные незнакомые вещи.
5. **Кузница — защита от повторного нажатия и устаревших данных.** Новое атомарное вычисление `forgeAttempt` считывает самый свежий кошелёк, состояние предмета и уровень героя перед расходом ресурсов. Быстрое повторное нажатие не ставит две параллельные операции. Если предмет изменён в другом окне игры — устаревший запрос отвергается без списания. Не обещает защиты от прямой подделки через Supabase API.
6. **Кузница — предпросмотр следующего уровня:** реальный результат канонической формулы (включая то, что критический шанс не растёт). RU/EN текст и шансы успеха сохранены.
7. **Бой:** ровно один выбранный спутник участвует в Походе/Испытаниях. Его атакующая и защитная специализация учитывается в боевом расчёте, маг и охотник имеют умеренные разные PvE-эффекты, целитель не оживляет погибших и не лечит выше максимума. Общий лимит урона по элитным врагам из пакета 2 сохранён.

## Безопасность экономики: подтверждённая проблема действующей базы

15 октября 2026 **только чтением метаданных Supabase** установлено, что роль `authenticated` всё ещё имеет `UPDATE` и `INSERT` по `players.game_state`, `players.gems`, `players.gold`, `players.level`, а RLS для `players` разрешает клиенту редактировать собственную строку (`update_own_player`). Следовательно, игрок с авторизованной сессией может подделывать личные ресурсы и характеристики, несмотря на UI-проверки. Это не исправляется только TypeScript-кодом.

В `supabase/staged/` добавлены:
- `territory_stage4_security_preflight.sql` — read-only список проверок grants, RLS и функций сервера; изменений живой базы не делает.
- `territory_stage4_LOCKDOWN_DRAFT.sql.example` — *специально заблокированный* пример финального отзыва прав. Текущая игра пишет клиентские сохранения, поэтому немедленный `REVOKE` сломает игру. Проект моста включает серверные подтверждения всех игровых действий, сверку старых кошельков, проверку Telegram-авторизации, резервную копию, интеграционные тесты под параллельными запросами и только затем отзыв прямой записи. Эту миграцию **не применяли**.

**Серверная экономика по-прежнему НЕ защищена.** Никаких SQL-миграций к рабочей базе, включения оплаты, начисления наград сезонов или изменения боевого PvP не делалось. Следующий обязательный этап — настоящий server-authoritative cutover без потери игровых данных; отдельная авторизация владельца нужна перед изменением рабочей базы.

## Регрессии и сборка

`npm run test:stage4`: миграция старых спутников, уровневые пороги, выбор одного активного, стоимость/лимиты, типы бонусов, внутриигровая кузница против повторных списаний и гонок, 7-слотовые PvE-бонусы, боевой учёт бонусов, синтаксис проекта.

`npm run test:economy`: включает stage 1, 2, 3 и 4. Обычные проверки `test:balance`, `test:professions`, `test:feature-separation`, `test:mobile-home` и Telegram остались.

Изменения локально протестированы без модификации серверной БД; полную сборку TypeScript/Vite подтверждает GitHub Actions после загрузки архива. `economy-release.json.ready` оставлен `false`. Публикацию делать только после успешной сборки нового распакованного коммита через `Territory - publish working game (restore Pages)`.

## Установка

Положить в корень ветки `main` одним коммитом одновременно:
- `TERRITORY_STAGE4_FULL.zip.part01`
- `TERRITORY_STAGE4_FULL.zip.part02`

НЕ добавлять рядом старые части `.zip.part*` и не добавлять собранный ZIP. После зелёного `Install uploaded project ZIP` проверить `npm run test:economy` и `npm run build` на коммите авто-распаковки, затем опубликовать его.
