# TERRITORY — инструкция исполнителю

## Задача и самостоятельность

Последнее прямое поручение владельца определяет задачу и важнее этого файла. Владелец делегировал техническое управление репозиторием: самостоятельно исправлять, упрощать, проверять и завершать работу без повторного согласования обычных обратимых действий. Не превращать пожелание в постоянный запрет, не добавлять новые требования от имени владельца.

Этот файл — единственная общая инструкция. `CLAUDE.md` и `START-HERE-RU.md` только направляют сюда. Документы с датами, старые очереди, issue и handoff — контекст; их назначения и запреты не возобновлять автоматически. Проверять текущий код и фактическое состояние задачи.

Один ответственный исполнитель доводит текущую задачу до результата. Дополнительный агент полезен только для конкретной независимой работы; отдельные роли, согласования специалистов и служебные issue не обязательны. Автоматическая «команда» из профилей и экспериментальных dispatch-workflow удалена. Не изображать запуск недоступных исполнителей.

## Что сохранять

- Одна работающая игра **TERRITORY**: React 18, Vite 5, TypeScript, Telegram WebView, Supabase. Продолжать существующую реализацию, не создавать вторую игру или дубли систем.
- Прогресс, валюты, VIP, предметы, экипировку и аккаунты игроков. Не сбрасывать данные, не проводить реальные платежи и не выдавать настоящие награды клиентским кодом. Не менять админский вход, секреты или баны заодно с UI.
- Серверные квитанции, идемпотентность, совместимость сохранений и защиту доступа. Не ослаблять проверки ради зелёного CI и не тестировать с записью в живые аккаунты.
- Утверждённый арт и игровые правила. Нужные для задачи требования — [GAME_REQUIREMENTS_RU.md](docs/GAME_REQUIREMENTS_RU.md); стиль — [ART_STYLE_LOCKED_TERRITORY_V1_20261027_RU.md](docs/ART_STYLE_LOCKED_TERRITORY_V1_20261027_RU.md). Не читать всю историю проекта перед каждой небольшой правкой.

Общее техническое управление не означает сброс живой базы, смену экономики или массовую рассылку. Изменение production должно быть необходимо конкретной задаче, сохранять данные и иметь проверенный план перехода и отката. Сначала подготовить и проверить реализацию; отдельный опасный шаг не останавливает независимые безопасные части работы. Сообщения игрокам отправлять только по поручению на конкретную публикацию.

## Порядок работы

1. Проверить `git status`, ветку и актуальный код. Сохранять чужие изменения. Если работа идёт в GitHub, сверить свежий `main` и пересекающиеся PR.
2. Исправить причину и закончить один проверяемый сценарий. Не расширять задачу инфраструктурой, переписыванием рабочих режимов или дополнительными отчётами без необходимости. Для связного изменения использовать ветку и PR; локальные обратимые правки можно коммитить без отдельного разрешения.
3. Выполнить `npm run typecheck`, `npm run lint`, `npm run build` и относящиеся к изменению тесты из `package.json`. Не удалять падающие тесты и не менять их ожидания только ради прохождения. Повторять проверки при новых изменениях или обнаруженной проблеме.
4. При изменении интерфейса пройти путь игрока, проверить узкий экран и RU/EN; для Пещеры — 320/360/390/430 px и малую высоту. Проверку Chromium не называть проверкой физического телефона или Telegram WebView.
5. Проверенную безопасную работу завершать самостоятельно. Не сливать незавершённый/красный PR и не включать безусловный auto-merge. Сначала PR и проверки, затем выпуск; выпуск не является условием подготовки PR.
6. Единственная публикация игры — `.github/workflows/pages.yml`, `main`, GitHub Pages. После выпуска проверить workflow и опубликованный SHA (`node scripts/check-published-pages.mjs`). Vercel в этом проекте не используется.
7. Коротко сообщить по-русски: результат, проверки, где увидеть, что не проверено. Issue, план, PR и локальная сборка сами по себе не означают выпуск.

## Где продолжать

- [DEVELOPMENT_RU.md](docs/DEVELOPMENT_RU.md) — запуск, карта кода и текущая реализация Пещеры.
- [CAVE_EXPEDITION_DEMO_RU.md](docs/CAVE_EXPEDITION_DEMO_RU.md) — существующий изолированный забег. Реальный путь `BattleScreen → ServerAdventureScreen` сохраняет 100 этажей, попытки и серверные награды; DEMO не обращается к данным игрока. Не смешивать их награды и сохранения.
- Пакет 21 персонажа уже есть в трёх `TERRITORY_art_v2_Codex_*_of_3.zip`; `python3 scripts/check-character-art-pack.py` проверяет архив. Это исходные изображения, не готовая анимация. Не запрашивать их повторно и не заменять глобальный арт ради DEMO.
- Референсы Lootborn нужны для соответствующего нового игрового дизайна, а не для исправления сборки или документации. Использовать подтверждённые материалы повторно; недоступный экран отметить, продолжая независимую работу.

Неподтверждённые игровые цены, награды и формулы не выдавать за решение владельца. Для локального DEMO допустимы явно тестовые значения; их нельзя переносить в настоящую экономику без определения правил. Обновлять устаревший пункт на месте, а не дописывать противоположное правило.
