# TERRITORY — правила для исполнителей

Это единственный действующий свод правил. Если правило где-то ещё (в старых документах, ТЗ, очередях) противоречит этому файлу, действует этот файл. История решений хранится в `docs/`, а не здесь.

## 1. Что это за проект

- **TERRITORY** — живая Telegram-игра (React + Vite + TypeScript, сервер на Supabase). У игры около 110 настоящих тестеров с сохранённым прогрессом.
- Ветка `main` сама публикуется на GitHub Pages через `.github/workflows/pages.yml`. **Любой коммит в `main` сразу попадает к игрокам.**
- TERRITORY 2.0 — отдельный проект. Не смешивать их.
- Vercel не используется. Ничего на нём не создавать и не удалять.

## 2. Запрещено всегда (без отдельного письменного разрешения владельца)

1. Менять, сбрасывать или удалять прогресс, валюты, VIP, инвентарь и экипировку игроков.
2. Трогать production-базу Supabase, миграции, Edge Functions, секреты и правила авторизации.
3. Начислять награды или валюту на стороне клиента. Любая награда подтверждается сервером.
4. Проводить реальные платежи.
5. Менять вход в админку (5 нажатий на «прогресс сохранён»), пароли владельца и правила автоматических банов.
6. Заменять или удалять утверждённый арт (список — в разделе 6).

Если задача упирается в один из этих пунктов, остановиться и спросить владельца. Остальное делать без лишних вопросов.

## 3. Как вносить изменения

| Что меняется | Куда | Что запустить перед этим |
|---|---|---|
| Тексты, стили, картинки, вёрстка одного экрана | Можно сразу в `main` | `npm run typecheck`, `npm run lint`, тест экрана |
| Новая механика, несколько экранов, логика игры | Ветка → pull request → зелёные проверки → слияние | То же + тесты затронутых разделов |
| Сохранения, экономика, награды, авторизация, админка, сервер | Ветка → pull request → зелёные проверки → **согласие владельца** | То же + `npm run test:economy` / `test:saves` |

- Новая механика сначала делается как **тестовая версия**: видна в игре, но изолирована от настоящих наград (фальшивые покупки, тестовый доступ). Сервер, защиту и админку доделывают **после** того, как владелец её одобрил.
- Новый ресурс или валюта, который реально выдаётся игрокам, в том же изменении получает управление в админке: просмотр баланса, выдача и списание с проверкой на сервере.
- Черновики не сливать в `main`. Одна задача — одна ветка. Не править одни и те же файлы параллельно с другим исполнителем.

## 4. Когда задача считается сделанной

Все пункты сразу:
1. Код и нужные картинки в `main`.
2. Публикация на GitHub Pages прошла успешно (указать SHA коммита).
3. Экран проверен на ширине 360 px (скриншот приложить к отчёту).
4. Указано, что **не** проверено.

Иначе писать «в работе», а не «готово». Макет, картинка, тикет или открытый pull request — не результат.

## 5. Отчёт владельцу

- По-русски, коротко: что сделано, где в игре нажать, чтобы увидеть, что не проверено, что мешает.
- Не писать «готово», если не выполнен раздел 4. Не называть подмену картинки анимацией.

## 6. Визуальный стиль

Подробности и картинки-эталоны: [`docs/ART_STYLE_LOCKED_TERRITORY_V1_20261027_RU.md`](docs/ART_STYLE_LOCKED_TERRITORY_V1_20261027_RU.md). Эталонные экраны в игре: **Лавка** и **Арена**.

**Нужно:** яркий мультяшный викинг; тёмный дуб с видимыми волокнами, кованый металл, верёвка только там, где она что-то держит; крупный жирный читаемый шрифт; герой крупно, а не маленькая иконка.

**Нельзя:** плоские коричневые плашки вместо дерева; одинаковые рамки и верёвки на каждой строке; огромные кнопки; перекрытые надписи; одна большая картинка вместо интерактивного экрана; выдуманные цифры (уровни, проценты), которых нет в игре.

Сложная графика — это отдельные PNG/WebP в `public/assets/territory/`. CSS только для раскладки.

**Утверждённый арт (не заменять):** `public/*-viking.webp` (7 зелий), `public/assets/territory/characters/heroes/`, `docs/art-reference/*`.

## 7. Игровые правила, которые нельзя ломать

- Экипировка универсальна для всех внешностей героя.
- В бою герой смотрит вправо, противник влево, герой на 20–30% крупнее.
- Расходники живут 7 дней, тратятся сначала самые старые.
- Арена: ручной выбор направления атаки и блока. Профессии и аукцион остаются.

## 8. Команды

```
npm ci               # установка
npm run dev          # локальный запуск
npm run typecheck    # проверка типов
npm run lint         # линтер (0 ошибок обязательно)
npm run build        # сборка
npm run test:<раздел>  # тесты раздела, список в package.json
```

## 9. Как менять эти правила

Владелец правит этот файл целиком: заменяет устаревший пункт, а не дописывает новый раздел сверху. Без дат, эмоций и описания прошлых провалов в тексте правил. Конкретные задачи и очередь — в `docs/territory-v1-release/CODEX_QUEUE_RU.md`, а не здесь.
