# TERRITORY — ПАКЕТ 2: усиленный PvE, исправленные задания, спутник и сохранения

Основа: **пакет 1, установленный в main**, коммит `fbc1311b85b5b1f6b3b4b47be5109a6ebc4be169` от 15 октября 2026.
Пакет — **полный исходный проект**, а не отдельный патч. Это важно: `unpack-project.yml` использует `rsync --delete` для файлов проекта.

## Изменения в работающей игре

1. **Поход:** главы 1–3 оставлены прежними для начинающих. С 4-й главы сложность растёт плавно. К 100-й главе обычные враги и боссы получают примерно до +40% здоровья, +30% атаки, +34% защиты относительно прежней линейной формулы. Все пять типов обычных врагов усиливаются одинаковым правилом.
2. **Испытания:** дополнительные усиления постепенно нарастают до 60-го этажа: примерно +24% здоровья, +15% атаки и защиты поверх нового PvE-множителя.
3. **Защита элитных противников:** боссы в Походе получают не более 48% своего максимального HP урона за один *раунд*; стражи Испытаний — не более 40%. Считается суммарный урон героя **и спутника**, а не лимит для каждого отдельно. Это препятствует мгновенному прохождению тысяч этажей после старых ошибок экипировки; уже пройденные этажи НЕ откатываются.
4. **Спутник «Верный щит»:** его защита теперь работает в PvE, снижая входящий положительный урон в пределах примерно 12% (с учётом силы щита и минимально возможного урона 1). Атака спутника сохраняется.
5. **Еженедельное задание:** теперь обновляется по воскресеньям в 00:00 **Europe/Kyiv**; летнее/зимнее время учитывается. У старых персонажей при первом чтении задания НЕ стираются. Ежедневные, сюжетные задания и достижения не сбрасываются из-за нового еженедельного таймера.
6. **Камни и повторные нажатия:** одна попытка начать PvE-бой больше не может списать два камня из-за двойного клика/перекрытия автозапуска. Стоимость по-прежнему один камень.
7. **Облачные сохранения:** в пределах одной игровой вкладки новые снимки могут заменить старые *ещё не отправленные* изменения; сетевые запросы по-прежнему упорядочены. Это уменьшает очередь ненужных сохранений при быстрых действиях. При уходе приложения в фон последняя ожидающая запись отправляется немедленно, без 1,5-секундного ожидания. Начальный сервисный перенос экипировки больше не держит загрузочный экран открытым до ответа сети.
8. **Лавка:** во время нажатия «Купить» снова читается актуальный каталог и действующая скидка. Закрывшаяся распродажа не оставляет старую цену в уже открытом окне.
9. **PvE-боёвка:** равномернее перемешиваются зоны блока; неправильные/отрицательные усиления эликсиров отклоняются.

## Что намеренно НЕ меняется

- Прогресс и имущество пользователей, этажи, уровни, VIP, профлицензии, синие алмазы, внутриигровые цены, опыт за бой, награды, стоимость камней и суточный лимит 25 покупаемых камней.
- Сила и правила серверной Арены/PvP — отдельно, не подменяются клиентом. Аукцион и реальные платежи не включаются.
- База Supabase, RLS, SQL-миграции, Auth/Telegram, `.github` workflow-файлы не изменяются.
- **Это НЕ завершение защиты экономики.** Прямые изменения `players.game_state`, `players.gems` через авторизованный клиентский API и локальные крафт/награды остаются уязвимыми. Переход на серверные атомарные действия, квитанции и отзыв прав записи — следующая обязательная фаза. Не применять незавершённую миграцию 20261013211739 отдельно.

## Проверки перед выпуском

- `npm run test:stage2`: календарь по Киеву (включая смену времени), сохранение старых наград, усиление врагов, запрет мгновенного убийства босса/стража, активная защита спутника, проверки эликсиров и очереди сохранений.
- `npm run test:balance`, `npm run test:professions`, `npm run test:feature-separation`, `npm run test:mobile-home`, `npm run test:client-guard`.
- `npm run test:progression` — таблица изменения противников на 1, 5, 20, 58, 81 и 3000 этажах.
- `npm run test:economy` по-прежнему запускает SQL-проверки PGlite, затем client-guard, новые проверки и анализ прогрессии.

Без `node_modules` в локальном контейнере полный Vite/TS проект нельзя собрать здесь; после загрузки ZIP GitHub CI выполнит сборку на актуальных зависимостях. При ошибке публикация не должна происходить. Прежде чем считать версию опубликованной, проверь зелёную сборку именно нового коммита и опубликуй его через **Territory - publish working game (restore Pages)** (старый `pages.yml` пока пропускает deploy из-за `economy-release.json.ready=false`).

## Установка

Одновременно загрузить в **корень main** ровно две части: `TERRITORY_STAGE2_FULL.zip.part01`, `TERRITORY_STAGE2_FULL.zip.part02`. GitHub Action сам соберёт архив, проверит его, распакует проект и удалит части. Не загружай один объединённый ZIP вместе с частями и не оставляй от старого пакета другие `*.zip.part*`.
